# 유사서비스 비교연구

**조사 기준일:** 2026-06-11(가격·외부 서비스 기능은 당시 스냅샷이며 현재 제품 계약이 아님)<br>
**대상:** Metabase · Redash · Apache Superset · Grafana · Luzmo · MongoDB Atlas Charts
**용도:** 차트 솔루션 기능 범위 결정 참고. 마지막 장에 본 프로젝트와의 매핑 포함.

표기: ✓ 지원 / △ 부분·제한 지원 / 💰 유료 플랜 전용 / ✗ 미지원

## 자체 구현 판단 근거

**개선 목표:** 범용 대시보드 전체를 다시 만드는 것이 아니라 사내 PostgreSQL 차트를 프레임워크 독립 SDK로 삽입하는 요구에 가장 비용 효율적인 build-vs-buy 경계를 정한다.

**선택 근거:** 현재 요구의 핵심은 범용 BI 기능 수가 아니라, 제한된 차트 범위를 사내 데이터·권한·배포 정책에 맞게 통제하면서 SDK로 재사용하는 것이다. 따라서 전체 제품 도입보다 필요한 계층만 직접 소유하는 쪽을 현재 선택으로 삼았다.

| 검토 대안 | 장점 | 현재 요구에서의 비용 | 현재 선택과 이점 | 검증·재평가 조건 |
|---|---|---|---|---|
| Metabase | 노코드·질의·대시보드 성숙 | 원하는 native SDK·세밀한 host 통합·브랜딩은 배포/플랜 제약 | 노코드 개념은 참고하되 차트 단위 SDK를 자체 구현 | 임베드 요구·총소유비용 재비교 |
| Superset | 넓은 차트·권한·대시보드 기능 | Celery·Redis 등 운영 복잡도와 제품 범위가 현재 요구보다 큼 | 기능 상한선 참고, 경량 배포 유지 | 대시보드·권한 범위 확대 시 재검토 |
| Grafana | 옵션 패널·관측 데이터 시각화 UX 성숙 | 업무 관계형 노코드 builder와 저장 모델이 목표와 다름 | 옵션 탐색 UX만 참고 | 사용자 테스트로 옵션 구조 검증 |
| Redash | SQL 중심 탐색이 단순 | 비개발자 builder와 native embed 관리 기능이 부족 | schema browser·SQL workspace 개념 참고 | SQL 탭 도입 시 재검토 |
| 상용 embedded analytics | 지원·완성도·화이트라벨 | 비용·벤더 종속·사내 데이터 배포 조건 | 현재 사내 범위는 자체 구현, 규모 확대 시 build-vs-buy 재평가 | 사용자·기능·운영 인력 증가 시 TCO 검증 |

자체 구현의 핵심 이점은 “대시보드 전체”가 아니라 PostgreSQL 기반 차트 정의·캐시·JWT와 프레임워크 독립 SDK를 필요한 범위만 소유하는 것이다. 반대로 인증·대시보드·알림·고급 접근성까지 요구되면 상용/OSS 도입이 더 경제적인지 다시 비교해야 한다.

## 10. 본 프로젝트 관점 정리

### 우리가 만드는 범위 (위 표와 매핑)

| 영역 | 우리 MVP | 비고 |
|---|---|---|
| 차트 생성 | 노코드 빌더(MVP, 날짜 버킷팅·원본 데이터 탭·모든 차트 원본값 튜플 모드 포함) → SQL 직접 작성(2차) | Metabase 모델 |
| 차트 종류 | 막대·선·원형·산점도·박스 플롯·행렬 히트맵·영역 지도·포인트 지도 8종 | ECharts 기반 추가 유형 확장 여지 |
| 시각화 옵션 | 레지스트리 기반 공통·차트별 옵션(개별 색 지정 포함) | Grafana 옵션 패널 구조 |
| 대시보드 | ✗ (차트 단위 임베드로 대체) | 모든 경쟁 서비스가 보유 — 의식적 제외 |
| 임베딩 | div 네이티브 + JWT (핵심) | Metabase에선 💰인 영역 |
| 데이터 소스 | PostgreSQL 다중 등록 + 동적 풀 | Metabase/Redash 표준 구조 |
| 인증 | 사용자 토큰(MVP) + 임시 로그인 골격 → SSO 교체 | 임베드 구조는 인증 방식 무관 |
| 자동화·알림 | ✗ | 전 서비스 보유 — 후속 검토 대상 |

### 표에서 드러나는 시사점

1. 대시보드·알림·스케줄은 6개 서비스 전부가 가진 기능이다. 우리 MVP에서 뺀 것은 정당하나, 사용자 기대치에는 존재할 수 있다. Post-MVP 1순위 후보.
2. 네이티브 임베드 + 토큰 인증을 무료로 제공하는 곳은 Superset(guest token)과 MongoDB Charts(Mongo 전용) 정도다. 범용 + 가벼움 + PostgreSQL이라는 우리 포지션은 비어 있다 — 자체 구축 정당성 유지.
3. 쿼리 파라미터(변수)는 전 서비스 공통이며 임베드 차트의 활용도를 크게 높인다(예: 부서별로 같은 차트). 옵션 확장보다 먼저 올 가능성이 있는 요구 — 토큰·SQL 설계에 파라미터 자리를 염두에 둘 것.
4. Superset은 기능이 가장 넓지만(50+ 차트, RLS, 전 기능 무료) 운영 복잡도가 가장 높다(Celery, Redis 등). "기능 상한선" 참고용.
5. 행 수준 보안(RLS)은 대부분 유료 영역이다. 우리에게 "사용자별 자기 데이터만" 요구가 오면 유료급 기능을 만드는 것임을 인지하고 비용을 산정할 것.
