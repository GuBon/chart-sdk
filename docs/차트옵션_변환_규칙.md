# 차트옵션 변환 규칙

**문서 버전:** v1.3 (2026-08-07 갱신: ColorBrewer 직접 소유 팔레트로 전환)

**관련 문서:** [제품요구사항](제품요구사항.md) · [화면설계서](화면설계서.md) · [인터페이스 계약서](인터페이스_계약서.md)

**기준 코드:** `chart-options/optionRegistry.ts` (`OptionDef[]`) · **대상:** Apache ECharts 6.1 · **DB:** PostgreSQL

> 이 문서는 "방식 A"(PRD 6)의 운영 변환기를 정의한다: **(rows, chartType, options) → ECharts option JSON**. 임베드 조회(API 1)·노코드 미리보기 실행(API 2A `run-builder`)·옵션 재조립(API 2B `/charts/preview`)은 **서버 Java 변환기**를 운영 권위로 공유한다. `admin/mocks/mockTransform.ts`는 MSW 기반 프론트 테스트를 위한 테스트 미러일 뿐 운영 조립 경로가 아니다. `chart-options/transform-parity-contract-cases.json`의 8종 기본값과 구성 사례 18개는 양쪽의 **전체 JSON 출력**을 비교하며, 레이아웃·분석 세부 규칙은 분야별 공용 fixture가 보강한다.

## 1. 원칙

1. **레지스트리가 매핑의 소스다.** 각 `OptionDef.echarts`가 ECharts 경로다. 두 종류뿐이다.
   - **직접 경로** (예: `title.text`, `series.lineStyle.width`): 값을 그 경로에 그대로 set.
   - **특수 핸들러** (`@`로 시작, 예: `@series.type`, `@yAxis.formatter`): 아래 6장의 함수가 처리. 단순 1:1이 아닌 것(파생·결합·구조 변경)만 핸들러로 둔다.
2. **첫 컬럼 = X축/이름, 나머지 숫자 컬럼 = 시리즈/값** (PRD 6.1). 이 컨벤션은 집계 결과와 원본값 튜플(`agg:"none"`) 모두에 동일하게 적용되며, 피벗(breakout) 이후에도 유지된다.
3. 변환기는 **(rows → [피벗] → series 조립) → option 조립** 단계 구조다. `builderConfig.seriesBy`가 있는 막대·선은 `SeriesPivot`이 두 번째 그룹 차원을 열로 전개한다. `map`·`geoscatter`는 지역·좌표 한 행의 의미를 보존해야 하므로 피벗하지 않고 `__chartsdk_series` 값별 ECharts series를 직접 만든다.
4. `options`의 미해당 키(다른 대분류 전용 등)는 **무시·보존**한다 — 절대 에러 내지 않는다(7.2 전환 규칙 호환).
5. 누락 키는 레지스트리 기본값으로 채운다(`defaultsFor(chartType)`로 머지 후 조립).
6. **데이터 의미와 저장된 설계 크기·글꼴 기반의 결정적 레이아웃은 변환기, 실제 컨테이너 크기·반응형은 렌더러 책임**이다. 변환기는 `options.display`·`options.typography`로 글꼴과 점유 높이를 계산하지만 DOM 크기를 강제하지 않는다. 제목의 실제 폭과 resize 갱신은 SDK·Admin 미리보기가 공용 `chart-options/renderLayout.ts`로 주입한다.

### 1.1 테마 레지스트리

`chart-options/colorBrewerSchemes.ts`는 ColorBrewer 2.0의 정성형 8개, 순차형 18개, 발산형 9개, 총 35개 공식 최대 클래스 HEX 배열의 단일 원본이다. `chart-options/palettes.ts`는 선택·방향·차트 전환만 담당한다. 막대·선·원형·산점도·박스플롯·포인트 지도에는 정성형만, 영역 지도·히트맵에는 순차형과 발산형만 제공한다. 순차형은 공식 9색, 발산형은 공식 11색을 ECharts `visualMap` 정지점으로 전달하고 프로젝트의 HEX 선형 보간만 사용한다. 정성형 색이 부족하면 임의 색을 만들지 않고 선택한 ColorBrewer 배열을 순환한다.

저장 계약은 `colorTheme.version = 4`다. `V9__colorbrewer_palettes.sql`은 기존 `mc_chart` 전체를 일반 차트 Dark2, 영역 지도·히트맵 Blues로 갱신하고, 이전 체계에서 남은 `autoColorMap`·`colorMap`·`itemColorOverrides`를 비운다. 따라서 마이그레이션 직후 기존 차트도 ColorBrewer로 통일되며, 이후 사용자가 v4 UI에서 새로 지정한 개별 색상은 유지된다.

UI에서 **테마**는 색 조합과 배정 규칙을 고르는 프리셋, **스타일**은 테마·색·배경·글꼴·차트 고유 외형, **계열**은 시리즈 종류·라벨·정렬·범례를 뜻한다. 계열별 지도 색도 외형 설정이므로 화면의 `스타일` 탭에서 편집한다.

## 2. 입력 / 출력

**입력**
```
rows      : { columns: [{name, type}], rows: any[][] }   // API 2/2A 결과 형태 (= mc_chart_cache.result)
chartType : 'bar' | 'line' | 'pie' | 'scatter' | 'boxplot' |
            'heatmap' | 'map' | 'geoscatter'              // mc_chart.chart_type (대분류)
options   : JSONB                                          // mc_chart.options (PRD 9.2)
```

`rows`는 SQL 생성 방식에 의존하지 않는다. `sum/avg/...` 집계 결과도, `agg:"none"` 원본값 튜플 결과도 변환기에는 같은 형태로 들어온다.
- bar/line: 첫 컬럼을 카테고리 X, 두 번째 이후 컬럼을 시리즈 값으로 사용.
- pie: 첫 컬럼을 `name`, 두 번째 컬럼을 `value`로 사용. 세 번째 이후 컬럼은 MVP에서 무시한다.
- scatter: 첫 컬럼과 두 번째 컬럼을 `[x,y]`로 사용. 버블 variant는 세 번째 이후의 지정된 숫자 컬럼을 크기 차원으로 사용하며, 그 컬럼은 별도 Y 시리즈나 개별 색 대상에 중복 포함하지 않는다.
- boxplot: 첫 컬럼별로 두 번째 숫자 컬럼을 그룹화해 `[하한 수염,Q1,median,Q3,상한 수염]`을 계산한다. 수염은 1.5×IQR 범위 안의 실제 양 끝값이고, 범위 밖 원본값은 별도 scatter 시리즈로 분리한다.
- heatmap: 첫 컬럼=X 카테고리, 두 번째 이후 컬럼명=Y 카테고리, 각 값=`[xIndex,yIndex,value]`.
- map/영역: `__chartsdk_area_name`, `__chartsdk_area_value`, 선택 `__chartsdk_series`. PostGIS Polygon/MultiPolygon은 `__chartsdk_geojson`도 포함해 동적 지도로 등록한다. `map.name`은 `kr-sido|kr-sigungu`만 허용하고 알 수 없는 값은 `kr-sido`로 폴백한다.
- map/히트맵 및 geoscatter: `__chartsdk_longitude`, `__chartsdk_latitude`를 필수로 하고 `__chartsdk_point_name`, `__chartsdk_point_value`, `__chartsdk_size`, `__chartsdk_series`를 선택적으로 사용한다. 경도·위도 컬럼과 PostGIS Point가 SQL 계층에서 같은 계약으로 정규화된다.
- 지도 히트맵 데이터는 `{name,value:[lng,lat,intensity]}`, 포인트 데이터는 `{name,value:[lng,lat,value,size],symbolSize?}`다. 히트맵은 값 미선택 시 행마다 intensity 1을 쓰고, 선택한 값 하나를 강도와 색상에 함께 사용한다.

**출력** — ECharts option (API 1 응답 `option` 필드). 임베드 응답엔 `computedAt`도 동봉(7.7).

## 3. 조립 파이프라인

```
assemble(rows, chartType, options):
  opt = withDefaults(options, chartType)        # 누락 키 = 레지스트리 기본값
  rows = movingAverageOverridesSort(...)
    ? sortByTimeAscending(rows)                 # SMA는 시간 오름차순 강제(sortOrder 무시)
    : applySort(rows, opt.sortOrder)             # @sort (서버 정렬)
  cat, series = toSeries(rows)                  # 첫 컬럼=X, 나머지=시리즈 / [후속: 피벗]
  variant = resolveVariant(chartType, opt.variant)   # type 교체 + delta + flags

  o = {}
  applyTitle(o, opt)                            # 직접: title.text/left/top
  applyColor(o, opt, cat, series)               # @color / @colorMap
  applyLegend(o, opt)                           # @legend.position / @legend.type
  applyTooltip(o, opt, chartType)               # tooltip.trigger 직접 + @valueFormatter / axisPointer

  if isSpecial(chartType):                      # boxplot/heatmap/map/geoscatter 전용 조립
    o = buildSpecial(...)
    applyAnalysis(o, opt)                       # boxplot annotation + IQR outlier scatter
    return o

  if isCartesian(chartType):                    # bar/line/scatter
    applyGrid(o, opt)                           # grid.containLabel 직접 + @grid.preset
    applyAxes(o, opt, chartType, cat)           # x/y축 (@type/@formatter/@range/@second)

  o.series = buildSeries(chartType, variant, series, opt, cat)
  applyAnalysis(o, opt)                         # annotation + line SMA overlay
  return o
```

`isCartesian = chartType ∈ {bar, line, scatter}`. `boxplot`·`heatmap`은 전용 직교축과 grid를 만들고, `pie`·`map`·`geoscatter`는 일반 grid/axis 경로를 타지 않는다.

## 4. echarts 경로 = 직접 매핑 (그대로 set)

레지스트리에서 `@` 없는 경로는 값을 점 경로에 set한다(`setPath`). 시리즈 경로(`series.*`)는 **모든 시리즈에 동일 적용**하되, 개별 색(`@colorMap`)·이중축(`@yAxis.second`)처럼 시리즈마다 달라지는 것은 핸들러가 덮어쓴다.

| 옵션 | 경로 | 적용 위치 |
|---|---|---|
| `title` | `title.text` | option |
| `titleH` / `titleV` | `title.left` / `title.top` | option |
| `xAxis.title` / `yAxis.title` | `xAxis.name` / `yAxis.name` | option |
| `xAxis.rotate` | `xAxis.axisLabel.rotate` | option |
| `xAxis.verticalLabels` | 렌더 시 `xAxis.axisLabel.formatter` | option |
| `yAxis.verticalLabels` | 렌더 시 `yAxis.axisLabel.formatter` | option |
| `xAxis.splitLine` / `yAxis.splitLine` | `*.splitLine.show` | option |
| `xAxis.min/max` / `yAxis.min/max` | `*.min` / `*.max` | option (range·scale 핸들러가 선결) |
| `legend.show` | `legend.show` | option |
| `tooltip.trigger` | `tooltip.trigger` | option |
| `tooltip.axisPointer` | `tooltip.axisPointer.type` | option |
| `dataLabel` | `series.label.show` | bar·line·pie·scatter·heatmap·map |
| `labelPosition` | `series.label.position` | bar·line |
| `labelRotate` | `series.label.rotate` | bar·line·pie·scatter·heatmap·map (`dataLabel=true`일 때만, 0°는 내보내지 않음) |
| `palette` | `color` | option |
| `grid.containLabel` | `grid.containLabel` | option |
| `bar.width` | `series.barWidth` | bar 시리즈 |
| `bar.gap` | `series.barGap` | bar 시리즈 |
| `bar.borderRadius` | `series.itemStyle.borderRadius` | bar 시리즈 |
| `bar.showBackground` | `series.showBackground` | bar 시리즈 |
| `line.width` | `series.lineStyle.width` | line 시리즈 |
| `line.lineType` | `series.lineStyle.type` | line 시리즈 |
| `line.showSymbol` | `series.showSymbol` | line 시리즈 |
| `line.symbolSize` | `series.symbolSize` | line 시리즈 |
| `line.connectNulls` | `series.connectNulls` | line 시리즈 |
| `line.areaOpacity` | `series.areaStyle.opacity` | line 시리즈(영역 variant) |
| `pie.labelPosition` | `series.label.position` | pie 시리즈 |
| `pie.startAngle` / `pie.minAngle` | `series.startAngle` / `series.minAngle` | pie 시리즈 |
| `scatter.symbol` | `series.symbol` | scatter 시리즈 |
| `scatter.symbolSize` | `series.symbolSize` | scatter 시리즈(버블 아님) |

> `null` 값(예: `bar.width: null`, `min: null`)은 **set하지 않는다** — ECharts 기본값(자동)을 살린다.
>
> 단, pie의 `series.label.show`는 ECharts 기본값이 `true`이므로 `dataLabel=false`일 때도 반드시 `false`를 명시한다. `variant`와 `pie.labelPosition`은 라벨의 모양만 바꾸며 표시 여부를 켜지 않는다.

## 5. ECharts 본체 밖의 필드

`chart_type`·`description`·`refresh_mode`·`cache_ttl_seconds`·`refreshNow`는 JSONB 변환기 입력이 아니다.
- `chart_type`은 변환기 인자(chartType).
- `refresh_mode`·`cache_ttl_seconds`는 캐싱 계층(7.7)이 사용.
- `description`은 S1 카드 메타.
- `refreshNow`는 저장하지 않는 편집기 명령이다.

`showComputedAt`은 `options` JSONB에 저장되지만 ECharts option 자체의 필드는 아니다. 변환기는 이를 내부 메타데이터 `__chartsdkShowComputedAt`으로 내보내고 Admin 미리보기와 SDK가 계산 시각 캡션을 표시할지 결정한 뒤 `setOption()` 전에 제거한다. 과거 데이터처럼 키가 없으면 `true`로 처리한다.

## 6. 특수 핸들러 (`@`)

### `@series.type` — 대분류 → series.type
`bar→bar`, `line→line`, `pie→pie`, `scatter→scatter`, `boxplot→boxplot`, `heatmap→heatmap`. 지도 대분류는 `map/영역→map`, `map/히트맵→heatmap(coordinateSystem:'geo')`, `geoscatter/포인트→scatter(coordinateSystem:'geo')`, `geoscatter/효과 포인트→effectScatter(coordinateSystem:'geo')`다. bar·line에서는 `seriesTypes[시리즈명]`이 있으면 시리즈별 `bar|line`으로 오버라이드해 혼합(combo) 차트를 구성한다.

### `@variant` — 중분류 해석
`VARIANTS[chartType]`에서 선택 variant를 찾아 `{type?, delta, flags}`를 시리즈 조립에 반영.
- `delta`: 시리즈에 머지 (예: `smooth:true`, `step:'end'`, `areaStyle:{}`, `roseType:'radius'`).
- `flags`: 변환기 의미 플래그.

| 대분류 | variant | type | delta | flags / 처리 |
|---|---|---|---|---|
| 막대 | 기본 | bar | — | — |
| | 누적 | bar | — | `stack:'total'` → 전 시리즈 `series.stack='total'` |
| | 그룹 | bar | — | 스택 없음(기본 그룹 동작) |
| | 가로 | bar | — | `swapAxis` → X=value, Y=category 교환 |
| 선 | 기본/곡선/영역/누적영역/계단 | line | `smooth`/`areaStyle`/`step` | 누적영역은 `stack:'total'` 추가 |
| 원형 | 파이/도넛/로즈 | pie | `roseType`(로즈) | `donut` → `@pie.radius` |
| 산점도 | 산점도/버블 | scatter | — | `bubble` → `@scatter.bubble` |
| 상자수염 | 기본 | boxplot + scatter | IQR 요약 + 이상치 | 카테고리별 두 번째 값 컬럼 그룹화. 이상치는 같은 계열명의 scatter로 추가 |
| 행렬 히트맵 | 기본 | heatmap | visualMap | 행×값 컬럼을 셀 데이터로 변환 |
| 지도 | 영역 | map | visualMap | 행정구역명+값 또는 Polygon/MultiPolygon. `seriesBy`마다 map series 생성 |
| 지도 | 히트맵 | heatmap | `coordinateSystem:'geo'`, visualMap | 경도·위도/Point의 값 또는 행 밀도를 표시. `pointSize·blurSize·minOpacity·maxOpacity` 지원 |
| 포인트 지도 | 포인트 | scatter | `coordinateSystem:'geo'` | 이름·값·크기 역할과 계열 기준 지원. 크기값은 포인트별 6~28px 정규화 |
| 포인트 지도 | 효과 포인트 | effectScatter | `coordinateSystem:'geo'`, `rippleEffect` | 일반 포인트 역할에 표시 시점·파동 크기·주기·채움/윤곽 설정 추가 |

지도 계열이 둘 이상이면 범례를 유지한다. ECharts 6.1의 `visualMap.seriesTargets`로 영역 지도와 지도 히트맵의 값 차원(각각 0/2)을 명시한다. 포인트 지도는 visualMap을 사용하지 않고 테마·계열별 `colorMap[계열명]` 색상을 적용한다. 포인트 심볼·크기·불투명도·테두리·파동은 `geoscatter` 공통 점 스타일로 적용한다.

### `@caption.computedAt` — 기준 시각 캡션
`showComputedAt !== false`를 내부 메타데이터 `__chartsdkShowComputedAt`으로 전달한다. Admin 미리보기와 SDK는 응답의 `computedAt`이 있고 이 값이 `true`일 때만 `데이터 기준 YYYY-MM-DD HH:mm` 캡션을 그린다. 이 메타데이터는 ECharts에 전달하지 않는다.

### `@color` — 색 모드
- `palette`(기본): `option.color = opt.palette`. 시리즈/항목 색 미지정(ECharts가 순서대로).
- `individual`: `@colorMap` 적용.

### `@colorMap` — 개별 색
항목명/시리즈명 → 색. 매핑 규칙(PRD 7.2): **`colorMap`에 있으면 그 색, 없으면 팔레트 순서로 자동**(차트 안 깨짐).
- 막대·원형(단일 시리즈): 카테고리별 색 → `data[i] = {value, itemStyle:{color}}`.
- 선·다중 시리즈: 시리즈별 색 → `series[i].color` (또는 `lineStyle.color`/`itemStyle.color`).

### `@legend.position` — 위치 → 좌표 + 방향
| position | 설정 |
|---|---|
| top | `legend.top=(같은 모서리 제목 ? titleHeight : 0)`, `orient='horizontal'`, `type='scroll'` |
| bottom | `legend.bottom=(같은 모서리 제목 ? titleHeight : 0)`, `orient='horizontal'`, `type='scroll'` |
| left | `legend.left=0`, `orient='vertical'` |
| right | `legend.right=0`, `orient='vertical'` |

### `@legend.type` — 스크롤
상·하단 범례는 계산된 단일행 `legendHeight`와 실제 점유 높이를 일치시키기 위해 항상 `legend.type='scroll'`로 한 줄을 보장한다. `legend.scroll` 토글은 좌·우 세로 범례에서만 페이지네이션 사용 여부를 결정한다. 행렬 heatmap은 범례를 제거한다. map·geoscatter는 단일 계열이면 범례를 제거하고 `seriesBy`로 둘 이상이면 유지한다.

### `@tooltip.valueFormatter` — 값 포맷
`tooltip.valueFormat` → `tooltip.valueFormatter` 함수. 포맷 매핑은 9장과 동일.

### `@sort` — rows 정렬 (ECharts 아님)
`sortOrder`로 **rows를 첫 번째 값 시리즈(첫 숫자 컬럼) 기준** 정렬: `none`=원본, `asc`/`desc`=값 기준. 정렬은 series 조립 **전에** rows 단계에서 수행(축 라벨·값 동기 유지). 숫자가 아닌 값은 최솟값으로 취급하고 동순위는 입력 순서를 유지한다(안정 정렬). 정렬한 rows는 전용 조립 유형(boxplot·heatmap·map·geoscatter 포함) 모두가 공유한다.

**이동평균 우선 규칙:** `line` + 첫 열이 날짜·시간 타입 + `analysis.movingAverage.enabled`가 참이면 `sortOrder`를 적용하지 않고 시간 오름차순으로 정렬한다. 값 기준 정렬은 이동평균의 연속 구간 의미를 깨기 때문이다. 이 조건은 `chart-options/statisticalOverlays.ts`의 `movingAverageOverridesSort()` 하나로 정의하며 MSW 미러와 편집기 정렬 잠금이 같은 함수를 쓴다(화면설계서 4.4 정렬 잠금). 저장된 `sortOrder` 값은 지우지 않으므로 이동평균을 끄면 그대로 다시 적용된다.

### `@grid.preset` — 여백 프리셋
프리셋은 제목·범례를 제외한 **플롯 기초 여백**이다.

| preset | base grid |
|---|---|
| compact | `{ left:8, right:8, top:8, bottom:8 }` |
| normal | `{ left:24, right:24, top:28, bottom:24 }` |
| loose | `{ left:48, right:48, top:48, bottom:48 }` |

이후 `top += (상단 제목 ? titleHeight : 0) + (상단 범례 ? legendHeight : 0)`, `bottom += (하단 제목 ? titleHeight : 0) + (하단 범례 ? legendHeight : 0)`를 적용한다. `containLabel`은 별도 병합한다. heatmap은 범례 가산 대신 하단 `visualMapHeight`를 더한다.

### 논리 크기·글꼴과 동적 레이아웃

`options.display`는 차트를 설계한 **논리 캔버스 크기**이고 실제 임베드 DOM 크기는 아니다. 가로 `small(360×240)`·`standard(640×360)`·`large(960×540)`·`hd(1280×720)`·`fhd(1920×1080)`, 각 크기의 너비·높이를 뒤집은 세로 `smallPortrait(240×360)`·`standardPortrait(360×640)`·`largePortrait(540×960)`·`hdPortrait(720×1280)`·`fhdPortrait(1080×1920)`, 그리고 `custom`을 지원한다. custom은 240~3840×180~2160px로 제한한다. Admin에서 프리셋을 custom으로 바꿀 때는 현재 프리셋 크기를 `width/height`에 시드하고, 너비나 높이를 직접 편집하면 즉시 custom으로 전환한다.

글자 크기는 **요소별로 독립 판정**한다. `typography.{title,legend,axis,dataLabel,tooltip}FontSize`가 유한한 숫자면 그 요소만 직접 지정(제목 10~48px, 나머지 8~32px로 클램프)이고, `null`이면 자동이다. 자동은 프리셋별 제목/본문 기본값 `14/10`, `18/12`, `22/14`, `24/15`, `26/16px`에 `typography.scale(80~150%)`를 적용하며 대응하는 가로·세로 프리셋은 같은 단계를 쓴다. 사용자 지정 논리 크기의 자동 배율은 `clamp(pow((width×height)/(640×360), 0.25), 0.78, 1.5)`로 가로·세로를 함께 반영한다. 같은 종횡비에서는 기존 `sqrt(width/640)`과 같아 크기감을 유지하고, 높이만 바뀌어도 다시 계산된다. 직접 지정한 요소는 `options.display`나 `scale`이 바뀌어도 px를 재계산하지 않는다. 이 값은 `title.textStyle`, `legend.textStyle`, 축 `axisLabel/nameTextStyle`, `series.label`, `tooltip.textStyle`, `visualMap.textStyle`에 반영한다.

**폐기된 `typography.mode`(v0.7 이전의 auto/custom 일괄 게이트)** 는 변환기·편집기 공통 진입점(`migrateLegacyInteractionOptions`)에서 정규화한다. `mode='auto'` 저장분은 구 UX가 '자동' 복귀 시에도 직전 px를 남겼으므로 잔존 px를 **삭제**하고, `mode='custom'`은 px를 그대로 살린 뒤 `mode` 키를 제거한다.

글꼴은 `typography.{title,legend,axis,dataLabel,tooltip}FontFamily`에 요소별로 저장하며 각 값은 `default|pretendard|notoSansKr` 3종이다.

서버 Java 변환기와 MSW 미러는 다음 식을 공유한다.

```text
titleLines      = (titleDirection === 'vertical') ? max(1, 제목 코드포인트 수) : 1
titleHeight     = ceil(titleFontSize × 1.2) × titleLines + 4
legendHeight    = ceil(legendFontSize × 1.25) + 9
visualMapHeight = legendHeight + 12
```

기본 `standard`·100%·가로 제목에서는 각각 26/24/36px가 되어 기존 차트 외형을 유지한다.

- 제목과 범례가 같은 상·하 모서리이면 범례를 제목 다음 줄로 이동한다.
- map·heatmap 제목이 하단이면 `visualMap.bottom=titleHeight`로 제목 위에 배치한다.
- cartesian·boxplot grid는 제목·범례가 점유한 높이를 기초 여백에 가산한다.
- heatmap grid는 제목과 visualMap 높이를 함께 예약한다.
- pie·map·geoscatter는 grid가 없으므로 series/geo의 `top·bottom`에 제목·범례·visualMap 예약 높이를 반영한다.
- SDK·Admin ResizeObserver는 `chart.resize()`와 제목의 `width/overflow`만 갱신한다. 임베드 DOM이나 미리보기 viewport의 실제 크기 변화로 `fontSize`를 다시 계산하거나 패치하지 않는다.
- 이 식과 ECharts 경로의 동등성은 요소별 자동·직접 지정 혼합, 폐기된 `mode` 저장분, FHD 자동 글꼴, 가로가 같고 높이만 다른 custom 자동 글꼴, 세로쓰기 제목 사례를 포함한 공용 JSON 계약 픽스처를 서버 JUnit과 Admin Vitest가 각각 실행해 검증한다.

### `@typography.*FontFamily` — 요소별 글꼴

| 값 | 적용 |
|---|---|
| `default`(기본) | 아무 것도 내보내지 않아 ECharts 기본 sans-serif 렌더를 유지한다 |
| `pretendard` | 자체 배포한 `'ChartSDK Pretendard',sans-serif` |
| `notoSansKr` | 자체 배포한 `'ChartSDK Noto Sans KR',sans-serif` |

선택한 스택은 제목=`title.textStyle`, 범례=`legend.textStyle`/`visualMap.textStyle`, 축=`axisLabel`/`nameTextStyle`, 데이터 라벨=`series.label`, 툴팁=`tooltip.textStyle`에 각각 직접 넣는다. 루트 `option.textStyle`은 만들지 않아 한 요소의 선택이 다른 요소로 새지 않는다. `default`는 fontFamily를 내보내지 않아 ECharts 시스템 기본값을 유지하고, `pretendard`와 `notoSansKr`는 각각 `'ChartSDK Pretendard',sans-serif`, `'ChartSDK Noto Sans KR',sans-serif`를 내보낸다. SDK 빌드는 두 웹폰트와 OFL 사본을 `dist/fonts/{assetVersion}`에 포함하고 Admin 정적 폴더에도 복사한다. 버전은 `chart-options/assets.ts`가 단일 소스이며 URL 변경과 1년 immutable 캐시 무효화를 함께 책임진다. Admin과 임베드 SDK는 Canvas의 늦은 폰트 교체가 자동 재배치되지 않는 문제를 피하려고 현재 option의 문자열에 필요한 글리프를 `document.fonts.load`로 준비한 뒤 `setOption`을 호출한다. 구 전역 `typography.fontFamily` 저장본은 명시된 요소별 값을 보존하면서 비어 있는 다섯 요소에 전역 값을 복사한 뒤 구 키를 제거하며, 제거된 초기 선택값(`gothic|serif|mono`)은 `default`로 정규화한다.

### `@title.direction` — 제목 텍스트 방향

ECharts `title`은 회전을 지원하지 않는다. `titleDirection='vertical'`이면 제목 문자열을 **코드포인트 단위로 끊어 `\n`으로 결합**해 한 글자씩 아래로 쌓는다(서로게이트 쌍이 쪼개지지 않게 Java `codePoints()` / TS `Array.from`). 위 `titleLines` 항이 예약 높이를 줄 수만큼 늘린다. 세로 제목은 아래 "긴 제목 — 렌더러의 반응형 보정"의 폭 제한 대상에서 제외한다.

### `@dataZoom` — 휠 확대·축소

대분류가 막대·선·산점도·박스 플롯·행렬 히트맵이면 저장 옵션과 관계없이 다음을 붙인다. 따라서 Admin 미리보기뿐 아니라 SDK 임베드에서도 항상 휠 확대·축소가 가능하다.

```text
dataZoom = [{ type:'inside',
              xAxisIndex:[0]    (axis !== 'y'),
              yAxisIndex:[0,1]  (axis !== 'x' && 보조 Y축 사용),
              yAxisIndex:[0]    (axis !== 'x' && 단일 Y축),
              filterMode:'filter' }]
```

적용 축은 가로 막대가 Y축, 산점도·히트맵이 양축, 나머지가 X축이다. 과거 저장분에 유효한 `dataZoom.axis`(`x|y|both`)가 있으면 호환을 위해 그 값을 우선하지만 `dataZoom.enabled`는 무시한다. `type:'inside'`는 예약 높이가 0이라 제목·범례·grid 수식을 바꾸지 않는다. 하단 슬라이더(`type:'slider'`)는 예약 높이 계산이 추가로 필요해 도입하지 않았다(12장 확장 예약).

### 데이터 라벨 겹침

`dataLabel=true`인 bar·line·scatter·map·geoscatter 시리즈는 `labelLayout:{hideOverlap:true}`를 추가한다. pie는 ECharts 자체 원형 라벨 충돌 회피를 사용하고, heatmap은 셀 내부 고정 라벨이라 별도 layout을 적용하지 않는다. boxplot은 현재 편집기에서 데이터 라벨 옵션을 노출하지 않는다.

### `@xAxis.type` / `@yAxis.type` — 스케일 → 축 타입
- X축: 카테고리(기본) `type='category'`. 산점도(숫자 X)는 `xAxis.scale`로 `'value'`/`'log'`. 날짜 버킷팅 결과를 time축으로 쓰는 건 T3(`xAxis.type:'time'`).
- Y축: `yAxis.scale` `linear→'value'`, `log→'log'`.

### `@yAxis.unit` + `@yAxis.formatter` — 단위·포맷 결합
`yAxis.format`(숫자 포맷)과 `yAxis.unit`(접미사)을 **하나의 `axisLabel.formatter`로 결합**. 예: format=comma, unit=원 → `1,000원`. (9장 포맷 규칙 + `value + unit`.)

### `@yAxis.range` — 자동/수동
`rangeMode==='manual'`일 때만 `yAxis.min/max` 적용. `'auto'`면 둘 다 미설정(ECharts 자동). 0 기준 해제(`scale:true`)는 확장 예약.

### `@yAxis.second` — 이중축
`yAxis.secondAxis===true`:
1. `option.yAxis = [기본축, 2번째축]` (배열). 2번째축 `name/unit/format`은 UI 확장 시 별도 키, MVP는 기본 복제.
2. 시리즈 배정: 1번째 시리즈는 `yAxisIndex:0`, **2번째 시리즈부터 `yAxisIndex:1`** (기본 규칙). 추후 시리즈별 축 배정 UI로 세분.

### `@bar.normalize` — 100% 누적
`variant==='stacked'` && `bar.normalize===true`: 각 카테고리 합으로 나눠 비율(0~1 또는 %)로 변환. 변환기에서 데이터를 정규화하고 `yAxis` 라벨 `%` 처리.

### `@pie.radius` — 도넛 두께
`variant==='donut'`: `series.radius = ['{100-donutWidth}%', '100%']` (안/바깥 반지름). 파이는 `radius` 미설정(기본 원).

### `@scatter.bubble` — 버블 크기 인코딩
`variant==='bubble'`이고 `bubbleField`가 세 번째 이후 숫자 컬럼을 가리키면 해당 컬럼을 크기 차원으로 사용한다. JSON 응답에는 함수를 담을 수 없으므로 각 점을 `{value:[x,y,size], symbolSize}`로 조립하고, 유효 최솟값~최댓값을 제곱근 비율로 6~28px에 정규화한다. 값이 없거나 모두 같으면 `scatter.symbolSize`를 고정 크기로 쓴다. 크기 컬럼은 별도 Y 시리즈와 개별 색 대상에서 제외한다.

### `@map.name` — 행정 경계 자산
`map.name`과 `geo.map`은 같은 값을 사용한다. 허용값은 `kr-sido|kr-sigungu`이며 그 밖의 값은 `kr-sido`로 폴백한다. Admin 미리보기와 SDK는 이 이름으로 버전형 GeoJSON 자산을 등록한다.

### `map.boundary.*` — 포인트 지도 행정 경계 모양
포인트 지도의 `영역 → 행정 경계`에서 배경 행정구역을 편집한다. UI 순서는 행정구역 표시 → 경계 수준 → 채우기 색상 → 윤곽선 색상 → 윤곽선 너비이며 표시는 기본으로 켠다. `show=false`이면 보존된 모양 설정은 출력하지 않고 `geo.show=false`만 내보낸다. 색상은 자동(`null`)일 때 해당 `geo.itemStyle` 색상 속성을 만들지 않으며, 윤곽선 너비는 ChartSDK 기본 5px를 명시하고 0~20px로 제한한다. 직접 지정한 속성은 각각 `geo.itemStyle.areaColor`·`borderColor`·`borderWidth`로 전달한다. 이 설정은 영역 지도의 데이터 색상과 충돌하지 않도록 `geoscatter`에만 노출한다.

### 긴 제목 — 렌더러의 반응형 보정

서버는 컨테이너 실제 폭을 알 수 없으므로 `title.textStyle.width`를 만들지 않는다. SDK `renderChart`와 Admin `ChartPreview`가 공용 `chart-options/renderLayout.ts`를 통해 제목이 있을 때만 다음 값을 병합한다.

```text
title.textStyle.width = max(0, host.clientWidth - 32)
title.textStyle.overflow = 'truncate'
```

기존 `title.textStyle` 속성은 보존한다. `ResizeObserver`가 실행될 때 `chart.resize()` 후 동일한 title patch를 다시 `setOption()`하여 폭과 말줄임 정책을 갱신한다. 제목이 없으면 title 객체를 새로 만들지 않는다.

**세로쓰기 제목은 제외한다.** `title.text`에 `\n`이 있으면 폭 제한이 모든 줄을 한 글자 폭에 맞춰 잘라 버리므로, 최초 `setOption`과 resize 패치가 같은 술어(`usesResponsiveTitle`)로 주입을 건너뛴다.

## 7. 축 구성 규칙 (직교 차트)

- **카테고리 축**(막대·선·기본): 첫 컬럼이 X. `xAxis = { type:'category', data: cat, name, axisLabel:{rotate} }`.
- **가로 막대**(variant=가로): 축 교환 — `yAxis.type='category'(data:cat)`, `xAxis.type='value'`. name/min/max/format 등도 교환 축으로 따라감.
- **숫자 X축**(산점도): `xAxis.type='value'|'log'`, `data` 없음. 데이터는 `[x, y]` 쌍.
- **날짜 버킷팅 라벨**: 버킷 결과 라벨 포맷은 생성규칙 3A(month→`YYYY-MM` 등)에서 이미 적용된 문자열을 카테고리로 사용. (time축 전환은 T3.)

## 8. 색 매핑 상세

```
resolveColors(opt, cat, series):
  if opt.colorMode == 'palette': return { color: opt.palette }    # 순서 자동
  # individual: colorMap 우선, 없으면 팔레트 폴백
  pick(name, i) = opt.colorMap[name] ?? opt.palette[i % palette.length]
  # 단일 시리즈(막대·원형): 카테고리별
  # 다중 시리즈(선 등): 시리즈명별
```
- 폴백이 항상 있으므로 SQL 변경으로 새 항목이 등장해도 차트가 깨지지 않는다(PRD 7.2).

## 9. 숫자 포맷 규칙 (`format` 선택지 공통)

축 라벨·툴팁 값에 공통 적용.

| format | 변환 | 예 (1234.5) |
|---|---|---|
| raw | 원본 | `1234.5` |
| comma | 천단위 구분 | `1,234.5` |
| decimal0 | 정수 반올림(+천단위) | `1,235` |
| decimal1 | 소수 1자리(+천단위) | `1,234.5` |
| percent | ×100 + `%` | `123450%` |

Y축은 여기에 `unit` 접미사를 덧붙인다(@yAxis.unit+formatter).

## 11. 비호환 데이터 처리 (PRD 7.2)

| 대분류 | 비호환 상황 | 처리 |
|---|---|---|
| 원형 | 시리즈 2개 이상 | **첫 시리즈만** 사용. 나머지 폼은 회색 보존(복귀 시 복원) |
| 산점도 | X축이 카테고리(비숫자) | X 재선택 요구. 나머지 옵션 유지 |
| 상자수염 | 그룹/값 컬럼 부족 또는 값이 비숫자 | 빌더 검증에서 실행 차단. 변환기는 유효 숫자만 IQR 요약과 이상치 판별에 사용 |
| 행렬 히트맵 | 값 컬럼 없음 | 빌더 검증에서 실행 차단 |
| 지도 | 지역명/값 컬럼 부족 | 빌더 검증에서 실행 차단. 알 수 없는 지도명은 `kr-sido`로 폴백 |
| 포인트 지도 | 경도·위도 숫자 컬럼 부족 | 빌더 검증에서 실행 차단 |

변환기는 비호환이면 가능한 표현으로 폴백하되 에러를 던지지 않는다(임베드 비파괴, 화면설계 1.4).

## 12. 구현된 확장과 다음 지점

- **시리즈 분할(breakout, 구현됨)**: `SeriesPivot`이 `toSeries` 앞에서 `rows(x, seriesBy, 값) → x별 seriesBy 전개 → "첫 컬럼=X, 나머지=시리즈"`로 변환한다. 변환기 나머지는 불변이다(생성규칙 10장).
- **새 차트 대분류**: 레지스트리에 `appliesTo` 추가 + variant 정의 + (필요 시) 전용 좌표계 조립기. 레이더·캘린더·3D가 다음 확장 지점이다.
- **분석 표시(구현됨)**: `options.analysis.annotations.{lines,ranges,targets}`를 선택 계열의 `markLine`·`markArea`·`markPoint`로 조립한다. 값이 유효하지 않은 항목은 건너뛰고, 색상·두께·불투명도·기호·개수를 허용 범위로 제한한다. 가로 막대는 기준선·범위를 `xAxis`로, 목표 좌표를 `[값, 범주]`로 변환한다.
- **박스 플롯 이상치(구현됨)**: `options.analysis.boxplotOutliers.{show,color}`. Q1·median·Q3은 R-7 선형 보간으로 구하고 1.5×IQR fence 안의 실제 최소·최대를 수염으로 쓴다. 이상치는 고정 ID `__chartsdk_boxplot_outliers`의 scatter로 추가하며 박스 series와 이름을 같게 해 범례 동작을 공유한다. 기존 항목별 색·annotation은 요약 series에만 적용한다.
- **시간축 이동평균(구현됨)**: `options.analysis.movingAverage.{enabled,seriesIndex,period,showInLegend}`. `line`이면서 첫 열의 DB 타입이 date/time/timestamp일 때만 시간 오름차순으로 정렬하고 완전한 N개 숫자 창의 SMA를 계산한다. 최초 N-1개와 결측이 포함된 창은 `null`; 결과는 고정 ID `__chartsdk_moving_average_{seriesIndex}`의 line으로 추가해 원 계열 색·`yAxisIndex`를 상속한다. `showInLegend=false`이면 원본 계열만 `legend.data`에 명시한다. 이때 이동평균은 **이미 조립된 `legend`의 `data`만 조정**하고 범례 자체를 만들지 않는다 — `legend` 생략은 "기본 표시", `legend.show=false`는 "숨김"이라는 계약을 이동평균이 우회하지 않게 하는 경계다. 적용 조건이 참이면 `sortOrder`는 무시되고 시간 오름차순이 강제된다(아래 `@sort`).
- **휠 확대·축소(구현됨)**: 저장 설정 없이 직교 5종에 `dataZoom:[{type:'inside'}]` (`@dataZoom`)를 항상 조립한다. 차트 형태에 맞춰 축을 자동 선택하고, 과거 저장분의 유효한 `dataZoom.axis`만 호환한다. 예약 높이가 0이라 레이아웃 수식과 독립이다.
- **dataZoom 슬라이더·toolbox**: 하단 슬라이더(`type:'slider'`)와 toolbox는 확장 예약이다. 슬라이더는 차트 하단을 실제로 점유하므로 도입 시 `sliderHeight` 항을 grid 예약 수식에 추가하고 공용 fixture로 고정해야 한다. visualMap은 heatmap·map 전용 조립으로 구현돼 있다.
- **글꼴(구현됨)**: 제목·범례·축·데이터 라벨·툴팁별 `*FontFamily`에서 기본·Pretendard·Noto Sans KR를 선택한다. Pretendard와 Noto Sans KR의 variable WOFF2를 unicode-range 동적 서브셋으로 SDK와 Admin이 자체 배포하며 실제 사용 글리프만 선로딩한다.
- **텍스트 방향(구현됨)**: 차트 제목은 `titleDirection`(`@title.direction`)으로 글자를 줄바꿈해 실제 세로쓰기를 만들고, 데이터 라벨 지원 6종의 `labelRotate`는 90° 회전이다. 축 라벨의 `xAxis.verticalLabels`·`yAxis.verticalLabels`는 grapheme 단위 줄바꿈 formatter를 Admin·SDK가 렌더 직전에 복원하며, 기존 `axisLabel.rotate`를 보존하므로 세로쓰기와 회전을 동시에 적용할 수 있다. 서버 JSON은 함수를 담을 수 없으므로 각 물리 축에 `__chartsdkVerticalLabel` 역할 메타데이터를 전달하고 hydration 후 제거한다. 가로 막대에서는 논리 X/Y 역할을 보존해 교환된 물리 축에 적용하며, 히트맵의 범주형 Y축에는 숫자 단위 포맷을 섞지 않는다.
- **공용 계약 확장**: `transform-parity-contract-cases.json`은 8종 기본값과 구성 사례 18개의 Java/TypeScript 전체 JSON 출력을 직접 비교한다. 영역 지도 다중 계열, 지도 히트맵, effectScatter 계열별 파동 설정도 포함한다. `optionTransformCoverage.test.ts`는 레지스트리의 렌더 옵션을 차트 종류별로 하나씩 변경해 실제 출력 또는 런타임 메타데이터가 달라지는지 전수 검사한다. 레이아웃·분석의 세부 의미는 `layout-contract-cases.json`, `analysis-annotation-contract-cases.json`, `statistical-overlay-contract-cases.json`이 추가로 고정한다.
