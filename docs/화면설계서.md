## 1. 설계 원칙

1. 화면 단위가 아니라 상태(state) 단위로 설계한다. 빈 상태·로딩·성공·에러를 모두 프레임으로 만든다.
2. 내비게이션은 사이드바 없이 얇은 상단 바 하나로 통일한다. 이동 목적지가 적고(목록·설정), S2 편집 화면의 가로 공간을 최대로 확보하기 위함이다.
3. S2(편집)는 자체 3분할 레이아웃을 가지므로 전역 내비가 작업 공간을 침범하지 않게 한다.
4. 임베드(S4)의 실패가 호스트 페이지를 깨뜨리지 않는다. 차트 영역 안에서만 에러를 표시한다.
5. SQL 에러는 가공 없이 그대로 노출한다(메시지·라인 위치). 사용자가 즉시 수정할 수 있게.

### 벤치마킹 기준

| 참고 대상 | 가져올 것 |
|---|---|
| Grafana 패널 편집기 | 우측 시각화 옵션 패널 — 접이식 섹션 구조, 옵션 그룹화 |

| Metabase | 상단 바 중심 내비게이션, SQL 화면의 전체 흐름 |

## 3. S1 · 차트 목록

### 3.1 레이아웃

```
[상단 바 56px]
[페이지 헤더: "차트 목록" + 검색 입력(차트 이름·설명·소유자 부분일치, 240px) + (+ 새 차트) 버튼]  ← 높이 72px, 좌우 패딩 32px
[카드 그리드]                                  ← 4열(1440 기준), 거터 20px
```

| 영역 | 치수 |
|---|---|
| 콘텐츠 최대 폭 | 1200px 중앙 정렬 |
| 카드 | 폭 275px(4열 자동) × 높이 약 260px (설명 행 포함 시) |
| 카드 썸네일 | 카드 폭 × 110px, 모서리 8px |

### 3.2 카드 구성 (위→아래)

1. 썸네일 — 정적 미리보기(차트 종류 기반 일러스트 또는 저장 시 캐시 이미지). 실시간 SQL 실행 금지.
2. 차트명 (1줄 말줄임)
3. 설명 — 1줄 말줄임, text-secondary. 없으면 행 생략 (v2.2 추가)
4. 메타 행 — 종류 뱃지 + **차트 ID(#12, text-tertiary)** + 수정일 (+ 인증 도입 후: 소유자). ID는 관리·디버깅용이며 임베드 코드에는 포함하지 않는다.
5. 버튼 행 — [편집] [임베드] (호버 시 우상단에 삭제 아이콘 노출. 2차: 복제 아이콘 추가 — `POST /charts/{id}/duplicate`)
6. 관리자 로그인 시 — 목록에 모든 사용자의 차트가 보인다. 검색은 역할과 무관하게 하나(차트 이름·설명·소유자, 플레이스홀더 "차트 검색 (차트 이름, 설명, 소유자)"). 내 차트는 위와 같고, 타인(또는 소유자 없는 레거시) 차트는 버튼 행이 [열기] + "작성자 · 읽기 전용"으로 바뀌며 임베드·복제·삭제가 없다. [열기]는 `/admin/charts/{id}` 읽기 전용 상세로 이동한다.

### 3.3 상태 (Figma 프레임 3개)

| 프레임 | 내용 |
|---|---|
| S1-기본 | 카드 그리드 + 마지막에 점선 테두리 (+새 차트) 카드 |
| S1-빈상태 | 중앙: 아이콘 + "아직 만든 차트가 없습니다" + "첫 차트를 만들어 임베드해 보세요" + [첫 차트 만들기] |
| S1-삭제확인 | 모달(폭 400px): 제목 "차트 삭제" + 본문 "○○ 차트를 삭제할까요? 이 차트를 임베드한 모든 페이지에서 차트가 더 이상 표시되지 않습니다." (토큰은 사용자 귀속이므로 삭제되지 않음) + [취소] [삭제(danger)] |

### 3.4 동작

- [편집] → `/charts/{datasourceName}/{schema}/{mainRelation}/{chartId}`의 S2. [임베드] → S3 모달. [+새 차트] → `/charts/new`의 S2 신규. 모든 저장 차트는 URL 문맥을 위한 기준 관계를 가진다.
- 데이터: `GET /api/v1/charts` (API 계약 3.1).

## 4. S2 · 차트 편집 (핵심 화면)

### 4.1 레이아웃 (편집 헤더 + 3분할, 정의 모드 탭은 중앙 패널 내부)

```
[상단 바 56px]
[편집 헤더 52px: ←목록 | 차트명 (#12) | 저장 · 임베드 코드]   ← #id는 저장된 차트만(신규는 미표시)
┌─────────┬──────────────────────┬───────────┐
│데이터 패널 │  차트 구성 [접기]      │ 우측 기본   │
│데이터소스▾│  [노코드][SQL 준비 중] │ 360px     │
│─────────│  ▾ 차트 종류          │ 차트       │
│ 관계·     │  ▾ 데이터 구성        │ 미리보기(상)│
│ 컬럼 패널 │  + 생성된 SQL(접힘)    │───────────│
│ (SQL탭:  │──────────────────────│ 시각화     │
│ 스키마    │  [실행 결과]│[원본     │ 옵션(하)   │
│ 탐색기)   │   데이터] 탭 (하)      │           │
│ 기본 320px│                      │           │
└─────────┴──────────────────────┴───────────┘
```
> 우측 기둥 그림은 `아래쪽` 배치 기준이다. 옵션 배치가 `자동`(넓은 화면)·`왼쪽 고정`이면 시각화 옵션이 미리보기 **왼쪽**에 세로로 붙는다.

- 데이터소스 선택이 차트 정의의 첫 단계다. 미선택 시 탭·에디터 비활성. 셀렉트 목록은 S5에 등록된 전체 데이터소스(`GET /api/v1/datasources`).
- 데이터소스 셀렉트의 위치는 **좌측 관계·컬럼 패널 최상단** — 데이터소스 → TABLE/VIEW/MATERIALIZED VIEW → 컬럼의 수직 선택 흐름을 한 패널에 모은다(Redash 스키마 브라우저 패턴). 편집 헤더에는 두지 않는다.
- 데이터소스 셀렉트는 **왼쪽 목록의 탐색 범위**를 바꾼다. 기존 원본·축·조건은 유지하며, 원본 선택 중이면 새 원본 후보를, 조인 선택 중이면 다른 데이터소스까지 포함한 조인 후보를 보여준다. 실행·저장의 기준 데이터소스는 원본 관계에서 파생하고 여러 데이터소스 조인은 페더레이션 규칙을 따른다.
- 새 차트는 항상 노코드 탭에서 시작한다(기본 경로). 정의 모드 탭은 전역 헤더가 아니라 중앙 `노코드 구성` 패널 내부에 둔다. SQL 탭은 2차 구현 — MVP 프레임에선 비활성 탭으로만 표기한다.
- **저장된 차트로 진입하면 마지막 저장 캐시를 복원한다** — 단건 `GET /charts/{id}/preview`가 ECharts option과 집계 columns/rows를 함께 반환하므로 결과 표·차트가 즉시 채워진다. 편집기 자체는 고객 DB 쿼리를 자동 실행하지 않으며, 구성을 바꾼 뒤에는 명시적 [실행]으로 새 결과를 만든다. 신규 차트는 해당 없음. 목록 batch preview는 payload 절감을 위해 rows를 싣지 않는다.
- 노코드 탭: 좌측 패널이 원본·조인 관계의 **단일 선택기**이자 컬럼 탐색기로 동작한다. 중앙에는 관계 드롭다운을 중복 배치하지 않고, 기존 셀렉트와 같은 한 줄 높이의 선택 칸만 둔다. 평상시에는 현재 값과 화살표만, 클릭한 동안에는 파란 테두리와 `선택 중`만 추가한다. VIEW에는 `View`, MATERIALIZED VIEW에는 `Materialized View` 배지를 붙이고 갱신되지 않은 Materialized View는 `갱신 필요`로 비활성화한다. 좌측 기본 폭은 320px이고 펼쳐진 상태의 조절 범위는 200~480px이다. 경계를 왼쪽 끝(48px 이하)까지 끌면 데이터 패널을 자동으로 접는다. 우측 차트 미리보기·옵션 패널은 기본 360px, 최소 280px이며 고정 최대 폭을 두지 않는다. 중앙은 차트 구성 영역(차트 종류 + 데이터 구성)이다.
- **중앙 구성 패널의 최소 폭은 결과 패널 헤더의 실제 내용 폭에서 산출한다.** 탭 묶음·표본 배지·행 수 요약 등 헤더 항목의 실측 폭 합계(고정 항목은 실폭, 원본 테이블 라벨 같은 가변 항목은 72px 상한)가 최소 폭이며 하한은 480px이다. 우측 경계를 끌어 중앙이 이 폭 아래로 내려가면 헤더가 잘리기 전에 구성·결과 패널을 접는다. 좌측 데이터 패널은 종전처럼 48px 이하에서 접는다 — 즉 **중앙은 "읽을 수 있는 최소 폭"에서, 좌측은 "끝까지 끌었을 때" 접힌다.**
- 접힌 중앙 패널을 레일로 다시 펼칠 때는 최소 폭을 확보하기 위해 ① 현재 폭 유지 → ② 데이터 패널을 200px로 축소 → ③ 데이터 패널 접기 순으로 시도하고, 그래도 시각화 작업영역 최소 폭(280px)을 확보할 수 없으면 펼치지 않는다.
- SQL 탭(2차): 스키마 탐색기 + 에디터 + 결과. MVP에선 노코드의 "생성된 SQL 보기"(읽기 전용 접이식)가 SQL 가시성을 대신한다.
- 우측(차트 미리보기 + 시각화 옵션)은 두 탭 공통이다. 옵션 배치가 `자동`이면 가용 폭이 넓을 때 **미리보기 왼쪽**(구성 패널과 미리보기 사이), 좁을 때 아래로 전환하며 사용자가 `왼쪽 고정` 또는 `아래쪽 고정`을 선택할 수 있다 — 옵션과 데이터 구성을 오가는 시선 이동이 짧도록 오른쪽이 아니라 왼쪽에 붙인다. 두 영역 사이 구분선을 드래그해 옵션 폭·높이를 조절한다. **미리보기와 시각화 옵션은 개별 접기를 제공하지 않는다** — 둘은 항상 함께 보이며, 공간이 필요하면 우측 영역 전체 폭을 조절하거나 중앙 구성 패널을 접는다.
- 좌측 `데이터 패널`과 중앙 `차트 구성·결과`는 각 패널 헤더의 `접기`로 독립적으로 숨긴다. **두 패널 모두 `접기`를 헤더 행의 오른쪽 끝에 둔다** — 패널 이름은 왼쪽, 접기는 오른쪽 끝으로 고정해 패널마다 버튼을 다시 찾지 않게 한다. 구성 헤더의 실행 경고·안내 문구는 접기 버튼 왼쪽에 두고 폭이 모자라면 말줄임한다(접기 버튼은 줄이지 않는다). 접으면 패널의 원래 가로 위치에 40px 세로 복원 레일을 남긴다. 두 패널을 모두 접었을 때도 왼쪽부터 `데이터 패널 → 차트 구성·결과` 순서가 유지되며, 각 레일을 눌러 그 자리에서 펼친다. 중앙을 접으면 우측 **미리보기+옵션**이 남은 가로 폭을 채운다. 별도의 전역 `펼치기`나 `영역 확대` 모드는 두지 않는다.
- `전체 화면`은 최종 검수용 포커스 레이어를 브라우저 viewport 전체에 연다. 일반/중앙 패널 접힘/전체 화면에서 화면 맞춤·100%·25~200% 확대/축소를 제공하고, 넓어진 미리보기와 포커스 레이어에서는 너비 맞춤도 제공한다. 포커스 레이어에서는 브라우저 Fullscreen API도 선택적으로 사용할 수 있다.
- **저장된 차트를 편집할 때만** 데이터 패널 접힘, 차트 구성·결과 접힘, 옵션 배치, 좌·우 패널 폭, 결과·옵션 높이를 `localStorage` 편집 환경 설정으로 복원한다. 신규 차트(`/charts/new`)는 매번 기본 배치에서 시작하고 이 세션의 조절값을 저장하지 않는다 — 첫 화면이 항상 같아야 안내 흐름이 성립하기 때문이다. 현재 fit/zoom과 포커스 레이어는 차트 정의에 저장하지 않는다.

##### 신규 차트의 시각화 영역 잠금

신규 차트는 **[실행] 전까지 우측 미리보기·시각화 옵션 영역 전체를 잠근다.** 그릴 데이터가 없는 상태에서 옵션만 만지는 흐름을 막고 `구성 → 실행 → 꾸미기` 순서를 강제한다.

- 잠금 표현: 우측 영역을 딤 처리(불투명도·채도 감소)하고 그 위에 자물쇠 아이콘 + `먼저 차트를 실행하세요` + `왼쪽에서 데이터와 차트를 구성한 뒤 실행을 누르면 미리보기와 시각화 옵션이 활성화됩니다` 안내 카드를 중앙에 띄운다.
- 잠금 중에는 내부 컨트롤이 포커스·클릭 대상에서 빠진다(`inert` + `aria-hidden`). 레이아웃은 그대로 두어 실행 후 화면이 튀지 않게 한다.
- 해제 시점은 **[실행]을 누른 순간**이다(성공 응답이 아니라 실행 시작). 실행이 실패해도 다시 잠기지 않으며, 이후 같은 편집 세션에서는 저장·URL 정규화 후에도 계속 열려 있다.
- 저장된 차트로 진입하면 처음부터 잠기지 않는다 — 복원된 미리보기가 이미 있기 때문이다.

#### 차트 구성 영역 (중앙, 노코드 탭)

중앙 패널은 **독립적으로 접히는 두 작업 그룹**으로 나뉜다. 각 그룹 헤더는 제목(왼쪽) + 현재 상태 요약(오른쪽, 말줄임)으로 구성하고, 접어도 요약만으로 설정을 파악할 수 있게 한다. 둘 다 기본 펼침이며 서로의 접힘 상태에 영향을 주지 않는다.

| 그룹 | 내용 | 접힘 요약 예시 |
|---|---|---|
| **차트 종류** | 대분류(아이콘 그리드) + 중분류(세그먼트) | `막대 · 누적` — 중분류가 1개뿐인 유형은 대분류명만 |
| **데이터 구성** | 원본·조인·X축·Y축·시리즈·조건·정렬·표본추출 (아래 표) | `public.sales · 조인 1개 · X축 설정 · Y축 2개` / 미선택 시 `테이블을 선택하세요` |

**차트 종류를 시각화 옵션 패널이 아니라 구성 패널에 두는 이유**: 대분류·중분류는 꾸미기 옵션이 아니라 데이터 구성의 전제다(막대↔지도 전환 시 필요한 축·컬럼 자체가 달라진다). 구성 → 실행 → 꾸미기 흐름에서 첫 단계에 있어야 하며, 시각화 옵션 패널에는 중복 노출하지 않는다.

- 대분류: 아이콘 버튼 목록. 지리 계열(GEO)을 포함한 전체 대분류를 한 줄로 배치하고, 지리 계열 앞은 그룹명 없이 세로 구분선으로만 구분한다. 컨테이너 폭이 부족하면 자동 줄바꿈한다(`flex-wrap`). 아이콘 + 라벨을 한 줄에 가로 배치한다.
- 신규 차트는 대분류 기본 선택이 없다. 선택 전에는 어떤 버튼도 활성 표시하지 않고 중분류 행도 숨기며, 빌더 헤더의 빨간 안내는 '차트 종류를 선택하세요.'가 '테이블을 선택하세요.'보다 먼저 나온다. 종류를 골라야 실행·저장이 가능하다(기존 차트 편집은 저장된 종류가 선택된 상태로 열린다).
- 중분류: 세그먼트. 대분류 종속이라 선택 시 목록이 교체되며 **선택지가 1개뿐이면 행 자체를 숨긴다**. 선택된 중분류에 설명이 있으면 세그먼트 오른쪽에 보조 문구로 표시한다.
- 대분류 전환은 비파괴 규칙(아래 「차트 종류 전환 규칙」)을, 중분류 전환은 지도 계열의 `geoSeriesType` 동기화를 그대로 따른다 — 위치만 옮겼을 뿐 전환 의미론은 동일하다.

| 단계 | UI | 생성 SQL 대응 |
|---|---|---|
| 원본 | 현재 관계를 표시하는 선택 칸. 클릭하면 좌측 패널이 `원본 테이블 선택 중` 모드가 되고 목록에서 TABLE·View·Materialized View를 선택 | FROM (base) |
| 조인 | 관계 선택 칸·종류 INNER/LEFT·ON 좌=우 + **"조인 추가"** — base 다음, N개 체인. `조인 추가`는 임의 관계를 자동 지정하지 않고 좌측 선택 모드만 시작한다. 켜면 모든 컬럼 셀렉트가 `테이블.컬럼` qualified. 기존 표본 설정은 유지한다 | `[INNER\|LEFT] JOIN ... ON ...` (생성규칙 11장). 표본 사용 시 JOIN+WHERE 결과에서 RESULT_RANDOM 후 집계 |
| X축 | 컬럼 셀렉트 + **묶기 셀렉트**(일/주/월 — X축이 날짜 타입일 때만 노출, 기본 월) | GROUP BY + 첫 컬럼 (묶기 시 DATE_TRUNC + GROUP BY 1) |
| Y축 | 컬럼 + 집계 셀렉트(합계/평균/표준편차/분산/개수/고유 개수/최소/최대/원본값), 복수 행 추가 가능. 원본값 선택 시 모든 Y축이 원본값이어야 함 | SUM(col)·STDDEV(col)·VARIANCE(col) 또는 원본 `"col"` |
| 시리즈 나누기 | 선택 가능한 두 번째 그룹 차원 셀렉트. 지원 차트에서만 표시하며, 선택하지 않으면 계열 축/행 자체를 숨김 | GROUP BY 2차원 + 서버 피벗 |
| 조건 | [컬럼·연산자·값] 행 추가식 | WHERE |
| 정렬 | 컬럼 + 방향 | ORDER BY |
| 표본추출 | 토글 + `자동/직접 지정` + 직접 지정 시 1,000~50,000행 + [다시 뽑기]. 결과에는 방식·실측 표본 행 수·정확/표본 여부·집계별 경고를 표시한다. 세부 문구와 방식은 [표본추출 계약](표본추출_계약.md) 참조 | `builder_config.sample` |

- 포인트 지도를 선택하면 `좌표 방식`을 먼저 표시한다. `경도 · 위도 컬럼`은 기존 X=경도/Y1=위도/Y2=선택 크기 폼을 사용한다. `공간 Point 컬럼`은 카탈로그에서 인식한 SRID 지정 `geometry/geography(Point...)` 셀렉트와 선택적 숫자 `점 크기` 셀렉트만 표시하며 X/Y/정렬/표본 행은 숨긴다. 공간 컬럼은 WGS84로 자동 변환된다는 안내를 함께 표시한다.

- 하단에 "생성된 SQL 보기" 접이식 영역 — **기본 접힘**. 헤더 클릭 시 펼쳐져 노코드가 만든 SQL(읽기 전용)을 확인. 접혀 있어도 언제든 펼칠 수 있으므로 블랙박스 방지 원칙(생성규칙 1장)은 유지된다.
- 원본값 모드(`agg:"none"`)는 모든 그래프에서 선택 가능하다. 막대/선은 X/Y 행 값을 그대로 그리고, 원형은 name/value 행, 기본 영역 지도는 region/value 행을 그대로 그린다. 이때 생성 SQL에는 GROUP BY가 없으며 표본 추출을 켜면 선택된 원본 행만 표시한다.
- 기준 관계 선택 즉시 하단 [원본 데이터] 탭에 schema preview 원본 행이 표시된다(최대 1,000행 스크롤 — 4.2 사양 참조). 이후 JOIN·WHERE 구성이 바뀌면 원본 결과를 무효화하고, 사용자가 [원본 데이터] 탭을 열 때 조건 적용 raw를 지연 조회한다. [실행] 버튼은 집계 쿼리만 한 번 호출한다.
- **[실행]은 차트로 그릴 수 있는 구성에서만 활성화된다.** 차트 종류별 필수 축(X/Y) 또는 공간 전용 컬럼 구성이 완성되지 않으면 버튼을 비활성화하고 헤더에 사유(`X축 컬럼을 선택하세요.` 등)를 표시한다. 축 없이 조건·정렬 결과만 조회하는 별도 실행 모드는 두지 않는다 — 그 목적은 [원본 데이터] 탭이 전담하며, 실행 결과 탭은 항상 차트와 같은 집계 결과를 보여준다.
- SQL 탭으로 전환: 생성 SQL이 에디터에 로드(단방향). SQL 수정 시 "노코드 구성이 폐기됩니다" 경고.

### 4.2 스키마 탐색기 (좌)

- 최상단: **데이터소스 셀렉트** (4.1 위치 규칙) — 변경 시 소스변경확인 규칙 적용
- 선택 모드: 중앙의 원본/조인 선택 칸을 누르면 접혀 있던 데이터 패널을 자동으로 펼치고 검색 입력에 포커스한다. 검색 위에는 설명문 없이 `원본 테이블 선택 중` 또는 `N번째 조인 테이블 선택 중`을 한 줄로만 표시하고 좁아지면 줄바꿈 대신 말줄임한다. 대상 선택 칸도 파란 테두리와 `선택 중`으로 강조한다. 배너의 취소 버튼 또는 `Esc`로 구성 변경 없이 종료한다.
- 상단: 검색 입력 + 정렬/필터 메뉴. 검색은 현재 페이지가 아니라 전체 관계·컬럼을 대상으로 하며 검색어가 바뀌면 1페이지로 돌아간다.
- 정렬: 스키마·테이블 기본순, 이름 오름차순, 이름 내림차순. 필터: 데이터소스에 사용자 스키마가 2개 이상 있을 때만 스키마 선택 항목을 노출한다.
- 트리: 관계(펼침, `View`/`Materialized View` 배지) → 컬럼(이름 + 타입 작은 글씨). 탐색 목록은 클라이언트에서 페이지당 50개씩 표시하며 이전/다음과 현재 범위를 제공한다. `populated:false` Materialized View는 비활성화하고 `갱신 필요`를 표시한다.
- 빌더의 컬럼 타입 판정과 저장된 구성 복원에는 페이지로 잘린 목록이 아니라 API가 반환한 전체 스키마 원본을 사용한다. 페이지네이션은 탐색 UI 표시량만 제한한다.
- 동작: 선택 모드에서 **관계 클릭 → 지정된 원본 또는 조인 칸에 적용**한다. 원본을 처음 선택하면 즉시 하단 [원본 데이터] 탭에 schema preview를 표시하고(`SELECT * … LIMIT 1000`, 집계 실행과 별개), 기존 원본 교체는 조인·축·조건 초기화 경고를 확인한 뒤 적용한다. 조인 선택에서는 원본과 다른 조인에서 이미 사용 중인 관계를 비활성화한다. 선택 모드가 아닐 때 관계 클릭은 컬럼 트리만 열고 닫는다. (SQL 탭, 2차) 컬럼 클릭 → SQL 에디터 커서 위치에 이름 삽입
- 하단 영역은 **탭 2개**다: **[실행 결과]**(집계) / **[원본 데이터]**(raw, 세로 스크롤). [실행]하면 실행 결과 탭으로 전환하고 집계 요청만 보낸다. 구성에 맞춘 raw는 사용자가 [원본 데이터] 탭을 열 때 필요한 경우 한 번 조회한다. 구성 변경·재실행 시 이전 raw를 폐기하므로 집계와 상세 행이 어긋나지 않는다.
- 표본 실행 결과는 일반 열 오른쪽에 `표본 입력 행` 열을 두며, 결과 그룹 수와 집계 입력 표본 행 수를 구분한다. 집계별 배지·오차·경고 문구는 [표본추출 계약](표본추출_계약.md)을 따른다.
- [원본 데이터] 탭 사양: 노코드의 조건(WHERE)이 적용된 원본 행 = "이 차트가 집계한 바로 그 데이터". 최대 1,000행(미리보기 전용 제한)을 로드하고 세로 스크롤, 초과 시 "1,000행까지 표시" 안내(truncated). 실제 차트 결과에는 이 제한을 적용하지 않는다. 집계 쿼리는 여전히 자동 실행하지 않는다 — 명시적 [실행]만.
- 데이터: `GET /api/v1/schema/tables`, `GET /api/v1/schema/tables/{name}/preview` (경로명은 하위 호환을 위해 tables 유지, 응답은 관계 종류 포함)
- `mc_` 접두사 관계는 표시하지 않는다.

### 4.3 SQL 에디터 + 실행 (중) — SQL 탭 · 2차

- 에디터 하단 우측: [실행 ▶] 버튼 + 단축키 표기 (Ctrl+Enter)
- 실행 중: 버튼이 로딩 상태로, 결과 영역에 "쿼리 실행 중... (타임아웃 10초)"
- 성공: 결과 표 + 우측 상단에 "3행 · 42ms" 메타 표시
- 에러: 에디터 테두리 danger + 결과 영역에 에러 박스(메시지 + LINE 위치). 차트 미리보기는 갱신하지 않고 이전 상태 유지.
- 데이터: `POST /api/v1/query/run` (API 계약 2).

### 4.4 시각화 옵션 패널 (우) — Grafana식 접이식 섹션

패널 최상단에 옵션 검색창을 둔다. 옵션 이름·설명·섹션명을 실시간 검색하고 일치하는 섹션만 펼쳐 보여 주며, 결과가 없으면 빈 상태를 표시한다. 옵션 정의는 코드의 **단일 레지스트리(`chart-options/optionRegistry.ts` — `OptionDef[]`)** 로 관리하고 패널·서버 변환기·`options` JSONB가 모두 이 한 목록을 공유한다. 옵션 추가 = 정의 객체 한 줄.

#### 옵션 3존(zone) 구조

옵션을 "전역/차트별" 2분법이 아니라 **3존**으로 나눈다. 존은 저장 호환성과 차트 전환 시 유지/초기화 정책이며, 실제 편집 화면의 탭과는 별도 축이다.

#### 편집 탭 정보구조

| 유형 | 탭 순서 |
|---|---|
| 막대·선·산점도·박스 플롯·행렬 히트맵 | 기본 → 계열 → 축 → 스타일 → 상호작용 → 데이터 |
| 원형 | 기본 → 계열 → 스타일 → 상호작용 → 데이터 |
| 지도 | 기본 → 계열 → 영역 → 스타일 → 상호작용 → 데이터 |
| 포인트 지도 | 기본 → 계열 → 영역 → 스타일 → 상호작용 → 데이터 |

- 모든 차트는 `기본 → 계열 → 축/영역 → 스타일 → 상호작용 → 데이터`라는 같은 상대 순서를 사용하며, 적용할 옵션이 없는 `축` 또는 `영역` 탭만 생략한다.
- `테마`라는 사용자 용어는 유지한다. 테마·테마 색상·시리즈 색상·색상 방향·크기·전체 글자 크기·차트 고유 외형은 **스타일** 탭에 둔다. 지도도 별도 색상 편집기를 만들지 않고 같은 시리즈 색상 흐름을 사용한다. 포인트 지도의 모양·크기·불투명도·테두리·파동은 `점` 섹션의 공통 외형으로 편집한다. `테마`를 바꾸면 미지정 시리즈·요소의 기본색이 자동 변경된다. `테마 색상` 팔레트는 현재 선택한 시리즈 또는 차트 요소에 색을 지정하며 직접 지정 색과 함께 테마 변경 후에도 유지된다. `지정 해제`하면 현재 테마 기본색으로 돌아간다.
- 시리즈 종류·라벨·정렬·범례는 **계열** 탭에 둔다. 해당 정의가 하나도 없는 유형에는 빈 계열 탭을 만들지 않는다.
- **글꼴과 글자 크기는 해당 텍스트 요소를 편집하는 위치에 둔다.** 제목=기본, 범례=범례, 축=축 글자(축 탭), 데이터 라벨=계열, 툴팁=툴팁 모양에서 `기본·Pretendard·Noto Sans KR`와 요소별 px를 각각 고른다. `기본`은 ECharts 시스템 글꼴이고 Pretendard·Noto Sans KR은 ChartSDK 웹폰트 자산을 사용한다. 스타일 탭의 `글꼴` 섹션에는 자동 상태 요소에 적용되는 `전체 글자 크기`만 남긴다. 각 크기 슬라이더의 기본값은 **자동**이며 옆에 현재 적용 px(`자동 18px`)를 함께 표시하고, 값을 지정한 뒤에는 `자동` 버튼으로 되돌린다.
- 지도 역시 별도 탭 순서를 만들지 않고 공통 상대 순서를 따른다.
- 레지스트리의 `zone`은 저장/전환 정책, `OptionEditorTab`은 사용자 작업 순서다. 둘을 동일 개념으로 취급하지 않는다.

| 존 | 의미 | `appliesTo` | 대분류 전환 시 |
|---|---|---|---|
| **Zone 1 · 공통** | 모든 대분류 공통 | 8개 대분류 | **유지** |
| **Zone 2 · 좌표/축** | 직교 좌표계 차트 전용 | bar·line·scatter·boxplot·heatmap | 직교끼리 **유지** / 비좌표계 전환 시 **숨김+보존**(복귀 시 복원) |
| **Zone 3 · 대분류 전용** | 한 대분류 고유 | 해당 1개 | **초기화**(+토스트·실행취소) |

각 옵션에는 시급도 `tier`도 함께 단다(레지스트리 필드). **T1 = MVP 기본 품질**(없으면 차트가 어설픔), T2 = 자주, T3 = 고급. 존(구조)과 tier(시급도)는 직교 축이다.

**계열 · 분석 표시(구현됨):** 막대·선·산점도·박스 플롯에서 `options.analysis.annotations`를 편집한다. 기준선은 값·선 종류·두께·색상·라벨, 기준 범위는 시작/종료값·색상·불투명도·라벨, 목표값은 X 위치·값·기호·크기·색상·라벨을 가진다. 각 종류는 최대 12개이며 적용 계열을 선택할 수 있다. 서버는 선택 계열에 `markLine`·`markArea`·`markPoint`를 한 번만 연결해 조합 차트와 이중 Y축의 축 의미를 보존한다. 가로 막대에서는 값 축 방향을 `xAxis`로 자동 변환한다.

박스 플롯의 `options.analysis.boxplotOutliers`는 이상치 표시와 색상을 제어한다. Q1·중앙값·Q3은 R-7 방식으로 계산하고, 수염은 `Q1-1.5×IQR`~`Q3+1.5×IQR` 안의 실제 최솟값·최댓값이다. 범위 밖 원본값은 같은 계열명의 별도 ECharts `scatter`로 표시해 범례 토글이 박스와 이상치에 함께 적용된다. 선 차트의 `options.analysis.movingAverage`는 첫 결과 열이 날짜·시간 형식일 때만 활성화된다. 적용 계열·2~100 기간·범례 포함 여부를 편집하며, 서버는 시간 오름차순으로 정렬한 뒤 완전한 N개 구간만 단순 이동평균(SMA)으로 계산한다. 평균선은 원 계열 색상·Y축을 상속하고 2px 파선으로 표시한다.

**정렬 잠금:** 이동평균이 실제로 적용되는 동안(`선` 차트 + 첫 열이 날짜·시간 + 토글 ON) 변환기는 `sortOrder` 대신 시간 오름차순을 강제한다. 이때 `계열 → 라벨 · 정렬`의 `정렬` 셀렉트를 비활성화하고 `이동평균을 사용하는 동안에는 시간 오름차순으로 고정됩니다.`를 아래에 표시한다. **저장된 `sortOrder` 값은 지우지 않으며**, 이동평균을 끄면 잠금이 풀리고 이전 값이 그대로 다시 적용된다. 잠금 판정은 서버 변환기의 적용 조건과 같은 함수(`chart-options/statisticalOverlays.ts` 의 `movingAverageOverridesSort`)를 사용한다. 데이터 구성의 `정렬(ORDER BY)`은 실행 결과 자체의 순서라 잠그지 않는다.

확장 예약(후속, 접힌 상태로 표기만): dataZoom(줌·슬라이더), toolbox(이미지 저장·종류 전환), visualMap(조건부 서식·임계값 색), 영역 그라데이션, 0 기준 해제, 시간축(`xAxis.type:'time'`). (곡선·영역·누적·계단은 중분류 variant로 흡수)

#### 차트 종류 전환 규칙 (비파괴)

전환 정책은 옵션의 **존(zone)** 으로 일괄 결정된다 — "어떤 옵션을 지울까"를 개별 판단하지 않고 존 태그로 처리한다(레지스트리 `switchMajor()`).

- 데이터 구성(테이블·X·Y·조건·정렬)은 어떤 전환에도 초기화하지 않는다.
- 같은 대분류 내 중분류 전환(예: 기본 막대 → 누적): 옵션 전부 유지 — 즉시 재렌더만.
- 대분류 간 전환(예: 막대 → 원형):
  - **Zone 1(공통)** 은 유지.
  - **Zone 2(축)** 는 직교끼리(막대↔선↔산점도) 유지, 원형으로/에서 전환 시 숨김+보존(복귀 시 복원).
  - **Zone 3(대분류 전용)** 은 즉시 초기화 + 토스트 "막대 전용 설정이 초기화되었습니다 [실행 취소]" (`switchMajor()`의 `removedKeys` 사용).
- 비호환 데이터는 무시+안내: 원형 = 첫 번째 Y 시리즈만 사용(나머지 폼에 회색 보존, 복귀 시 복원) / 산점도 = 숫자 X 필요(비호환이면 X만 재선택 요구, 나머지 유지).
- 옵션 정의의 `appliesTo` + `showIf` 메타로 패널이 대분류별·조건별 옵션 노출을 필터링한다(`visibleDefs()`).

#### 색상 — 개별 색 지정 설계

- 팔레트 모드(기본): 색 배열을 순서대로 적용. 카테고리가 바뀌어도 깨지지 않음.
- 개별 지정 모드: SQL 실행 성공 후, 결과의 카테고리/시리즈가 행으로 나열되고 각 행에 컬러 피커. 실행 전에는 비활성("실행 후 지정 가능" 안내).
- 저장 형태(`options` JSONB): `colorMode`, `palette[]`, `colorMap{항목명: 색}`.
- 매핑 규칙: 항목이 `colorMap`에 있으면 그 색, 없으면(SQL 변경으로 새 항목 등장 시) 팔레트 순서로 자동 적용. 차트가 깨지지 않게 한다.

#### 데이터 형태 컨벤션 (서버 변환기 규칙)

- 첫 번째 컬럼 = X축(카테고리), 나머지 숫자 컬럼 = 각각 하나의 시리즈.
- 시리즈가 2개 이상이면 다중 막대/다중 선이 되고, 시리즈별 색·범례가 자동 구성된다.
- 전용 형태: 상자수염은 카테고리별 `[하한 수염,Q1,중앙값,Q3,상한 수염]`과 별도 이상치 점, 행렬 히트맵은 첫 컬럼×값 컬럼 매트릭스, 영역 지도는 지역명+값, 포인트 지도는 경도+위도(+크기값)로 변환한다. 포인트 지도의 [실행]은 지역·기간 등 사용자가 지정한 조건에 맞는 좌표를 고정 행 제한 없이 모두 가져오며, [원본 데이터] 탭은 계속 최대 1,000행만 표시한다.
- 제목·범례가 같은 상·하 모서리에 있으면 두 줄로 쌓고 grid 여백을 현재 글꼴의 단일행 높이만큼 늘린다. 예약 높이는 `ceil(제목 px×1.2)×제목 줄 수+4`, `ceil(범례 px×1.25)+9`, visualMap은 범례 높이+12로 서버·mock이 동일 계산한다. 긴 제목의 폭·말줄임은 실제 렌더 컨테이너 폭으로 계산하며 resize 때 갱신한다.
- 제목 텍스트 방향이 **세로**면 ECharts가 제목 회전을 지원하지 않으므로 변환기가 글자마다 줄바꿈을 넣어 쌓고, 위 수식의 줄 수가 글자 수가 된다(제목이 길수록 차트 영역이 줄어든다). 세로 제목은 폭 제한·말줄임 대상에서 제외한다 — 폭을 걸면 모든 줄이 한 글자 폭에 맞춰 잘리기 때문이다.
- 미리보기는 선택한 논리 크기(360×240~1920×1080 또는 custom)로 ECharts를 실제 렌더한 뒤 바깥 viewport에서만 CSS scale한다. 따라서 작은 패널에서도 FHD 글꼴·여백 계산을 FHD 기준으로 검수할 수 있고, 100%에서는 원본 픽셀 크기를 스크롤하며 확인한다.

- 옵션 변경 → 차트 미리보기 즉시 갱신 (저장 전에도 반영).
- 저장 데이터: `chart_type` 컬럼 + `options` JSONB. 옵션 추가 시 스키마 변경 없음.

### 5.1 레이아웃 (모달 폭 520px)

1. 제목: "임베드 코드" + 닫기 ✕
2. 사용자 선택: 셀렉트. 선택한 사용자와 차트에 묶인 키 상태를 표시한다.

### 5.2 코드 블록 내용

```html
<div data-embed-key="cek1_..."></div>
<script src="https://.../sdk.js"
        data-api-base="https://.../api서버"></script>
```

- 복사한 코드만 호스트 HTML에 붙이면 별도 초기화 없이 렌더되어야 한다. `script.src`는 SDK 자산 위치, `data-api-base`는 차트 데이터·지도 자산을 읽을 Spring API 위치이며 서로 다른 출처일 수 있다.
- Admin dev/build는 SDK 번들과 선택형 웹폰트를 `admin/public/sdk.js`, `admin/public/fonts/{assetVersion}/`로 자동 배포한다. 버전 경로의 폰트는 1년 `immutable`, 고정 이름 `sdk.js`는 매 배포 재검증한다. 운영에서 CDN을 쓰면 `sdk.js`와 `fonts/`를 같은 디렉터리 계층에 배포하고 `NEXT_PUBLIC_SDK_SRC`, API 위치는 `NEXT_PUBLIC_API_BASE`로 주입한다. 교차 출처 임베드에서는 CDN 폰트 CORS와 호스트 CSP `font-src`에 SDK 출처가 필요하다.

## 7. S5 · 데이터소스 관리 (코어로 승격)

상단 바에서 진입. 등록된 데이터소스 목록 + 추가/수정/삭제.

### 7.1 레이아웃

- 목록: 테이블형 (이름 · 호스트:포트/DB명 · 상태 점 · 연결 테스트 버튼 · 수정/삭제)
- [+ 데이터소스 추가] → 모달: 이름 / 호스트 / 포트 / DB명 / 계정 / 비밀번호 + [연결 테스트] + 안내문 "읽기 전용 계정을 권장합니다"

### 7.2 상태 (Figma 프레임 4개)

| 프레임 | 내용 |
|---|---|
| S5-목록 | 등록된 소스 테이블 |
| S5-빈상태 | "데이터소스를 먼저 등록하세요" + CTA (최초 진입 동선) |
| S5-추가모달 | 입력 폼 + 연결 테스트 성공/실패 인라인 표시 |
| S5-삭제확인 | "이 소스를 사용하는 차트 N개가 동작을 멈춥니다" 경고 |

- 비밀번호는 저장 후 다시 표시하지 않는다(변경만 가능).
- 수정 = 추가 모달 재사용: 기존 값 프리필, 비밀번호는 빈칸("변경할 때만 입력") — 입력 시에만 갱신(`PUT`의 dbPassword 선택 전달 규칙).
- 고급 설정(접이식): 커넥션 상한(max_pool_size, 기본 5) — 운영 DB 보호용.
- 데이터: mc_datasource. 사용 중인 소스 삭제 시 차트 영향 경고 필수.

### 7.3 데이터 카탈로그 탐색

- 메인 목록의 데이터소스 필터는 `/charts/{datasourceName}`으로 이동하고 동일한 카드·검색·종류·데이터소스·정렬·페이지네이션 UI에서 해당 범위만 표시한다. 스키마·관계 경로도 각각 `/charts/{datasourceName}/{schema}`, `/charts/{datasourceName}/{schema}/{relation}`에서 같은 목록 UI를 사용하며 기준 관계와 조인 보조 관계 참조를 모두 포함한다.
- 데이터소스 관리 목록의 이름은 `/charts/{datasourceName}?view=schema`으로 연결한다. 스키마 카드는 `/charts/{datasourceName}/{schema}?view=relations`, 관계 이름은 `/charts/{datasourceName}/{schema}/{relation}?view=columns`로 연결해 TABLE·View·Materialized View와 컬럼 정보를 명시적으로 탐색한다.
- 차트 범위 화면의 `데이터 탐색` 링크로 현재 깊이에 맞는 `view` 화면을 열고, 탐색 화면의 `차트` 탭으로 쿼리 없는 공통 목록에 돌아온다. 한글·공백 이름은 브라우저가 안전하게 인코딩한다.
- 탐색 경로는 상단 breadcrumb에 `데이터소스 > 소스 > 스키마 > 관계` 순서로 표시한다. 상단 GNB의 데이터소스 항목은 연결 관리 화면 `/datasources`에서 활성 상태다.
- 로딩·데이터소스 없음·스키마/관계 없음·검색 결과 없음·관련 차트 없음 상태를 각각 인라인 빈 상태로 처리한다.

## 8. 인증·관리자

### 8.1 로그인·회원가입

- 로그인: 중앙 카드(400px), 아이디·비밀번호. 성공 시 HttpOnly 세션 쿠키를 사용한다.
- 회원가입: 아이디·비밀번호·비밀번호 확인만 받으며 이메일은 받지 않는다.
- 보호 화면에 익명으로 접근하면 `/login?next=...`로 이동하고, 로그인 후 같은 origin 경로로만 복귀한다.
- 상단바는 현재 사용자와 로그아웃을 표시한다.

### 8.2 관리자 사용자

- `/admin/users`: 검색·상태·역할 필터, 차트 수·임베드 중 차트 수·활성 세션 수.
- `/admin/users/{id}`: 역할·상태 변경, 사용량 요약, 차트별 임베드 키 상태 이력.
- 임베드 키 원문은 표시하지 않는다. 사용자 비활성화는 세션과 활성 임베드 키를 함께 중단한다.

### 8.3 관리자 차트 읽기 전용 상세

- 별도의 "전체 차트" 탭·목록은 없다. 관리자는 S1 차트 목록(3.2 6항)에서 모든 사용자의 차트를 보고 차트 검색(소유자 매칭 포함)으로 좁힌다.
- `/admin/charts/{id}`: 저장 정의·SQL·미리보기의 읽기 전용 화면이다. 미리보기는 저장 스냅샷만 그리며, 스냅샷이 없는 차트(live 등)는 캔버스 대신 "저장된 미리보기 스냅샷이 없습니다…" 안내를 보인다 — 관리자 열람은 고객 DB를 조회하지 않는다.
- 저장·삭제·복제·임베드 키 발급 버튼은 제공하지 않는다.

## 부록. 현재 구현 반영 - S1/S2 보강

### S1 차트 목록

- 목록은 무한 스크롤이 아니라 페이지네이션으로 동작한다.
- 기본 `pageSize`는 8이며, 필터/정렬/검색 조건이 바뀌면 `page`는 1로 초기화한다.
- 정렬/필터링은 백엔드 `GET /api/v1/charts`에서 처리한다.
- 카드 미리보기는 더미 미니차트가 아니라 서버 preview option을 실제 ECharts로 렌더링한다.
- 현재 페이지의 미리보기는 `GET /api/v1/charts/previews?ids=...` batch API로 한 번에 가져온다.
- 새 차트 만들기 카드는 필터가 없고 1페이지일 때만 목록 카드 그리드 끝에 표시한다.

### S2 차트 편집 - 색상

- 색상 섹션의 팔레트 블록은 클릭 가능한 swatch로 표시한다.
- 선택된 swatch는 border/ring으로 구분한다.
- swatch 아래에는 선택 색상의 color input과 RGB 숫자 입력을 제공한다.
- RGB 값은 0~255 범위로 clamp하고, 변경 즉시 `options.palette[]`에 반영한다.
- `options.palette[]` 변경은 기존 옵션 preview 재조립 흐름을 그대로 타므로, SQL 재실행 없이 차트 미리보기가 갱신된다.
- 각 입력/select에는 `id` 또는 `name`을 부여해 브라우저 form field 경고를 방지한다.
