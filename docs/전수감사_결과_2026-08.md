## 종합 결론

엔지니어링 기본기는 사내 프로젝트치고 **이례적으로 성숙**합니다 — SQL 안전성, 자원 수명주기, 에러 계약, SSOT/parity, 프론트 경합 방어가 모범적입니다. 그러나 **인증 경계가 사실상 없어** 현 상태로는 배포할 수 없습니다. Critical 2건은 인터넷 노출 시 즉시 데이터 유출로 이어지며, 서로 다른 감사 3개가 독립 확인하고 원문으로 재검증했습니다. 품질 기반이 상위권이라 Critical 2 + High 9만 해소하면 실제 배포 가능한 수준에 빠르게 도달할 수 있는 구조입니다.

## 배포 차단 이슈 (Critical / High)

> "확인됨" 표시는 감사 결과를 원문 코드로 직접 재검증했다는 뜻.

### [Critical] 관리 API 전면 무인증 — 임의 SQL 실행 · 토큰 원문 유출 · 확인됨

인증 인터셉터가 `/api/v1/charts/data` 한 경로에만 걸려 있고 Spring Security 의존성이 없음(`WebMvcConfig.java:18`, `build.gradle.kts`). 결과적으로:
- `GET /api/v1/tokens`가 모든 JWT 원문을 반환(`TokenService.java:30,106`)
- `POST /api/v1/query/run`이 임의 SELECT를 고객 DB에 직접 실행
- 사용자 생성·데이터소스 자격증명 등록이 전부 무인증

인터넷 노출 시 `/tokens`로 유효 토큰 확보 → 전 차트 열람, 또는 `/query/run`으로 고객 DB 덤프가 가능.

**조치**: 관리 API 전역 인증(세션 또는 관리자 토큰) 도입, `/tokens` 응답에서 원문 제거(발급 시 1회만 노출·해시 저장), 관리·임베드 라우트 분리.

### [Critical] 임베드 토큰 chartId 스코프 부재 → 크로스 테넌트 노출 · 확인됨

JWT 페이로드는 `userId, jti, iat, exp, v`뿐 chartId 스코프가 없음(`JwtTokenProvider.java:32-37`). 임베드 조회는 `WHERE id=? AND (owner_id=? OR owner_id IS NULL)`인데(`EmbedChartService.java:64`), 유일한 `CurrentUserProvider` 구현이 항상 empty를 반환해(`DevelopmentCurrentUserProvider.java`) 모든 차트가 `owner_id NULL`로 저장됨. 유효 토큰 하나로 chartId를 1,2,3…으로 열거해 타 테넌트의 매출·좌표·PII 차트 결과를 전량 수집 가능.

> 참고: 이 무인증 상태는 인터페이스 계약서에 "임시"로 문서화된 **알려진 미완 항목**이며 신규 발견 버그가 아님.

**조치**: 토큰에 허용 chartId(또는 도메인) 스코프를 넣어 발급·강제, 운영용 `CurrentUserProvider` 실구현으로 교체, `owner_id IS NULL` 광역 허용 제거.

### [High] dev 시크릿 코드 기본값 + 운영 프로파일 부재 + fail-fast 없음 · 확인됨

단일 `application.yml`만 존재하며 JWT 서명키(`dev-chartsol-embed-secret-change-me`), AES 키, 메타 DB 비밀번호(`0218`)가 모두 fallback 기본값(:8,83,86). 환경변수 주입을 잊으면 운영이 dev 시크릿으로 조용히 기동. 평문 비밀번호에는 startup guard가 있지만 시크릿에는 없음. (서명키 위조는 `validateBearer`의 DB 재확인이 막지만, 서명 무결성·enc-key 유출 복호화 관점에서 High.)

**조치**: prod 프로파일에서 fallback 제거·필수화 + 기동 시 dev 문자열 감지 fail-fast(기존 `DatasourcePasswordStartupGuard` 패턴 재사용).

### [High] 내부 예외(SQL 원문 · DB 오류) 4종 클라이언트 노출

`SQL_ERROR`(422)·`FEDERATION_ERROR`·`SAMPLE_AGGREGATION_ERROR`·`DATASOURCE_QUERY_FAILED`가 `e.getMessage()`를 envelope message에 그대로 실어 PostgreSQL 원문 오류(컬럼·제약·테이블명), DuckDB/libpq 접속 오류(호스트·DB명)를 노출. 의도적 오류 SQL로 스키마를 열거하는 에러 기반 정보수집이 가능.

**조치**: 4종을 일반화된 사용자 메시지 + requestId만 반환하고 상세는 서버 로그로만.

### [High] SDK 로딩 상태·요청 타임아웃 부재 → 네트워크 hang 시 영구 빈 박스 · 확인됨

fetch에 AbortSignal/타임아웃이 없고 렌더 전 placeholder도 없음(`sdk/api.ts:22-25`). 응답이 지연·행되면 방문자는 오류도 로딩도 아닌 빈 div를 영구히 봄. 사용자가 강조한 "차트 실행/부재 시 내부 형식 안내" 관점에서 가장 취약한 지점.

**조치**: `AbortSignal.timeout(15s)` + 요청 시작 시 로딩 placeholder, 타임아웃 시 renderError 합류.

### [High] SDK 데이터 0행 empty state 부재 → 빈 축에 "정확한 결과" 캡션 · 확인됨

응답의 `rowCount`를 받고도 사용하지 않아(`sdk/api.ts:8`), 0행이면 서버 option을 그대로 setOption해 빈 좌표축 + "전체 데이터 · 정확한 결과" 캡션이 표시됨(`chart.ts:98-120`). "정확한 결과" 문구는 오해를 부름.

**조치**: rowCount 0 감지 시 "표시할 데이터가 없습니다" 디자인 placeholder(renderError와 동급의 인라인 스타일 잠금).

### [High] Admin — IN 조건 값을 타이핑으로 입력할 수 없음 · 확인됨

연산자 `in` 선택 후 값란에 "서울," 입력 → `splitList`가 빈 항목을 filter하고 join(', ')으로 되돌려 controlled input이 "서울"로 스냅백, 이어 "부산" 입력 시 "서울부산" 단일 값이 됨(`NocodeBuilder.tsx:934-937`). 다중 값은 붙여넣기로만 입력 가능.

**조치**: 입력 중 로컬 문자열 state 유지하고 blur/실행 시점에만 파싱, 또는 태그(칩) 입력 UI로 교체.

### [High] Admin — 차트 목록 API 실패가 "차트 없음" 빈 상태로 위장 · 확인됨

목록 로드 catch가 error state 없이 `setCharts([])`만 수행해(`useChartPage.ts:31-36`), 백엔드 중단 시 "아직 만든 차트가 없습니다 / 첫 차트 만들기" EmptyState가 표시됨. 운영자가 전체 차트 삭제로 오인 가능.

**조치**: catch에서 error state를 분리해 "목록을 불러오지 못했습니다 + 재시도" UI 표시.

### [High] Admin — 새로고침·탭 닫기에 이탈 경고 없음 → 미저장 변경 유실

이탈확인 모달이 인앱 [목록]·[새 차트] 버튼에만 작동하고 `beforeunload`/popstate 핸들러가 없음(`ChartEditor.tsx:1102-1105`). 편집 중 F5·탭 닫기·브라우저 뒤로가기로 변경이 경고 없이 사라짐.

**조치**: hasUnsavedChanges일 때 beforeunload 핸들러 등록/해제.

### [High] ChartOptionConverter 2,173줄 God class + 차트타입 if-체인 분기

시리즈 조립·축·여백 수식·타이포그래피·레거시 마이그레이션·boxplot 통계·이동평균이 한 클래스에 공존하고 타입 분기가 if-체인(`ChartOptionConverter.java:216-231`). 상태 없는 순수 변환이라 동작 위험은 없으나 새 차트 타입 추가 시 파일 내 6~8곳을 동시에 고쳐야 함.

**조치**: 타입별 SeriesAssembler 전략 맵 + OptionMigrations/레이아웃 협력 클래스 추출.

### [High] 패키지 순환 의존 — web이 사실상 최하층

`ApiException`이 web 패키지에 있어 query·cache·datasource·chart·converter 전부가 하위→web 역방향 의존을 갖고, query↔cache·cache↔federation·datasource↔query 패키지 순환 존재. 빈 그래프는 비순환이라 부팅은 되지만 모듈 분리(Gradle 멀티모듈·ArchUnit)가 불가능.

**조치**: ApiException을 common/error로, SamplingMetadata를 sampling 패키지로 이동. ArchUnit 의존 규칙 테스트 추가.

## 주요 Medium 발견 사항

- **자원 경합 3종**: 풀 생성 단일 전역 락으로 죽은 소스 하나가 다른 모든 소스 풀 생성을 최대 10초 직렬 블록(`DatasourcePoolRegistry.java:93-102`), lease 대기 sleep-폴링이 서블릿 스레드 최대 35초 점유(대기 인원 무제한), `/charts/previews`가 live 카드 최대 60건을 각 30초로 순차 재계산.
- **확장성 — kind 디스패처 부재**: 포트 이음매는 정확하나 종류별 라우팅 지점이 없고 PG 방언(TABLESAMPLE·ILIKE·DATE_TRUNC·setseed) 하드코딩. MySQL 추가 시 최소 10파일 + 스키마 마이그레이션.
- **Admin 주변 화면 catch 누락 4곳**: S5 연결 테스트 무반응+unhandled rejection(`datasources/page.tsx:33-41`), S7 토큰 로드/재발급 오류 무처리 + 재발급 더블클릭 시 토큰 2개 발급, EmbedModal 로딩 중/실패 시 "활성 토큰이 없습니다" 오표시.
- **공용 Modal 포커스 트랩·스크롤 락 부재 + 검색 디바운스 없음**: Tab이 배경으로 새고, 검색은 키마다 API 2건 + 목록 blank flash.
- **운영 환경**: CORS 출처 localhost 하드코딩(재빌드 강제), 관리 콘솔 next.config.mjs에 보안 헤더 전무, Spring Boot 3.3.5는 2025-06 OSS 지원 종료.
- **SDK**: 실패 후 재시도 불능(ATTR_DONE이 남음), 완전 무음 진단(호스트 개발자가 401/CORS 구분 불가), setOption throw 시 ECharts 인스턴스 누수.
- **계약서-구현 불일치 4건 + 서드파티 고지 누락**: `GET /users/{userId}/tokens` 미구현, 토큰 발급/회수/사용자 생성 상태코드(201/204/201 명세 vs 전부 200), 422 detail/position 미구현, NOTICES에 ECharts·DuckDB 누락.

## 잘된 점 — 유지할 자산

- **SQL 생성 안전성**: 식별자 화이트리스트 검증 후에만 인용 + 값 전면 PreparedStatement 바인딩 + ILIKE 이스케이프. 주입 경로 없음.
- **에러 envelope 단일 계약**: `{error:{code,message,fields,requestId}}` 강제 + 클라이언트 유발 예외는 절대 500이 아니라는 불변식.
- **자원 수명주기 관리**: 풀 참조카운트 세대 관리, DB lease 기반 다중 인스턴스 중복 제거, 정렬 세마포어 admission.
- **SSOT + parity CI 강제**: 옵션 정의 한 곳이 admin 패널·서버 defaults.json 구동, 매 push마다 Java/TS 변환 8종 snapshot deep-compare.
- **SDK 원시 오류 비노출**: 모든 실패가 단일 renderError로 수렴, DOM 삽입은 textContent만, 호스트 CSS 방어 치밀.
- **프론트 경합 방어**: requestId 가드 3종으로 stale 응답 덮어쓰기 차단, editorSnapshot 안정 직렬화로 정확한 dirty 추적.
- **JWT 검증 견고성**: alg=none 차단, HMAC 상수시간 비교, 폐기 즉시 반영, 비밀번호 AES-GCM + 평문 잔존 fail-closed.
- **테스트 계층화**: 단위/통합(*IT) 분리, TS mock 공유 계약 fixture, 포트 기반 fake, Flyway 패키징 바이트 검증.

## 우선순위 조치 로드맵

1. **관리 API 인증 경계 도입** (Critical · 배포 전 필수) — Spring Security/전역 인터셉터, /tokens 원문 제거, 라우트 분리
2. **테넌트 격리 확립** (Critical · 배포 전 필수) — 토큰 스코프 강제, 운영 CurrentUserProvider, owner_id IS NULL 제거, dev 시크릿 fail-fast + prod 프로파일
3. **SDK 오류 UX 3종 보강** (High · 사용자 강조) — 타임아웃+로딩 placeholder, 0행 empty state, 재시도/진단 코드
4. **Admin 동작 버그·에러 UX** (High · 사용자 강조) — IN 입력 수정, 목록 실패 위장 제거, beforeunload, catch 4곳, Modal 포커스 트랩
5. **내부 예외 노출 차단** (High) — SQL_ERROR 등 4종 일반화 메시지 전환
6. **운영 환경 정비** (Medium) — CORS 외부화, 보안 헤더, Boot 3.5.x, 자원 경합 3종 완화
7. **확장성 리팩터링** (High 구조) — ChartOptionConverter 전략 분리, ApiException 이동 + ArchUnit, datasource kind 디스패처
8. **계약·고지 정리** (Medium/Low) — 토큰 API 상태코드 정합, 계약서 에러코드 표 개정, NOTICES 추가, verifyChartDefaults gradle 태스크
