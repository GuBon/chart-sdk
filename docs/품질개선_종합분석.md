## 1. 조사 기준과 한계

저장소의 통합 세션 기록, git 커밋, 현재 설계·코드, Admin·SDK·Server 단위 테스트, MSW Playwright와 실제 PostgreSQL/PostGIS E2E를 교차 확인했다. 다른 세션의 원문 전체를 직접 다시 읽은 것으로 간주하지 않으며, 저장소에 구체화되지 않은 대화 내용은 사실로 추정하지 않는다. 상세 사건 식별자(A~N 계열)와 커밋 근거는 [개발 문제해결 이력](개발_문제해결_이력.md)에 보존한다.

### 문서화 구조 선택 근거

| 개선 목표 | 현재 선택 | 검토 대안 | 선택 이유와 현재 이점 | 한계·검증 |
|---|---|---|---|---|
| 현재 계약과 과거 판단이 섞이지 않게 함 | 전문 문서=현재 SSOT, 문제해결 이력=원문 | 하나의 전수 보고서, 모든 문서에 같은 규칙 반복 | 독자는 목적에 맞는 깊이를 선택하고 과거 값이 현재 계약으로 오인되지 않음 | 문서 간 사건 ID coverage 검사 필요 |

## 2. 결론

반복 문제의 공통 원인은 개별 버그보다 책임 경계와 권위 원천이 불명확했던 점이다.

- UI는 “무엇을 고르는가”와 “어떻게 꾸미는가”, 현재 입력과 마지막 성공 실행·저장을 뒤섞었다.
- 서버는 SQL·캐시·미리보기·임베드가 같은 데이터를 서로 다른 제한과 변환 규칙으로 해석했다.
- MSW 성공이 Spring·CORS·암호화·PostGIS·JWT의 실제 계약을 보장하는 것처럼 사용됐다.
- 구현된 기능이 문서에는 후속으로 남고, 같은 규칙이 여러 문서에 복제되어 서로 다른 버전으로 굳었다.

이에 따라 옵션 레지스트리, 서버 Java 변환기, 저장 스냅샷, 공용 계약 fixture, 실백엔드 E2E를 권위 경계로 도입했다. 현재 문서의 권위 배치는 [문서 안내](문서안내.md)를 따른다.

## 4. 현재 확정된 사용자 개념

- 테마는 여러 색의 조합과 배정 규칙을 고르는 ColorBrewer 프리셋, 스타일은 색·배경·글꼴·차트 고유 외형, 계열은 시리즈 종류·라벨·정렬·범례다. 정확한 테마 목록과 변환 규칙은 [차트옵션 변환 규칙](차트옵션_변환_규칙.md)에 둔다.
- 모든 차트는 공통 상대 탭 순서를 따르고 적용할 옵션이 없는 탭만 생략한다. 화면별 배치는 [화면설계서](화면설계서.md)의 권위다.
- `region_name`은 지도 경계 매칭, `sido_name`·`sigungu_name`은 각각 시·도와 시·군·구 분석·필터에 사용한다. 초기화 시점 드리프트와 현재 저장 관계는 [데이터모델 화면저장 매핑](데이터모델_화면저장_매핑.md)에 둔다.
- 수동 갱신에서 “서버 계산 성공”과 “Admin 화면 최신화 성공”은 별도 상태다. 정확한 호출 순서는 [인터페이스 계약서](인터페이스_계약서.md)의 갱신 API가 정의한다.

## 5. 벤치마크 사용 원칙

- ArcGIS에서는 지도 스타일·영역·상호작용을 작업 순서로 나누는 구조를 참고한다.
- Grafana에서는 오른쪽 옵션 패널, 섹션 접기, 옵션 검색을 참고한다.
- Redash에서는 스키마 브라우저와 SQL 작업 공간을 참고한다.
- Metabase에서는 노코드에서 SQL로의 단방향 전환과 임베드 개념을 참고한다.

용어와 탭 순서를 그대로 복사하지 않고 ChartSDK 데이터 모델과 실제 시리즈 존재 여부를 우선한다. 세부 비교는 [유사서비스 비교연구](유사서비스_비교연구.md)에 둔다.

## 6. 우선순위

### 배포 전

1. 100만행 fixture와 고객 DB 예산으로 15/30/100 VU 용량 gate를 실행한다.
2. Prometheus 규칙과 알림을 연결하고 actuator를 내부망에 격리하며 운영 secret/KMS와 CORS allowlist를 환경화한다.
3. `chartsdk.chart.update.version_missing=0`을 관찰한 뒤 별도 배포에서 version 강제 전환을 한다.
4. 외부 공개 전 Admin 인증/SSO, current user 주입, `owner_id IS NULL` 호환 경로 제거, 토큰·사용자 관리 API 보호를 끝낸다. 그전 배포는 내부망·제한 환경으로 한정한다.

### 데이터 신뢰성과 운영

1. `POST /charts`에 Idempotency-Key와 DB 유일성 보장을 추가한다.
2. 갱신 실행 이력, 스케줄, 장시간 작업 queue·취소·진행률을 추가한다.
3. 표본 OFF/raw SQL exact 대형 결과를 streaming/columnar 경로로 전환한다.
4. 대용량 Polygon 단순화와 최종 option 크기 정책을 정한다.
5. 다중 인스턴스 admission·runtime version과 datasource generation 상태 정리 정책을 완성한다.

### 제품 확장

1. Figma 보드 `169:2`를 현재 화면설계와 맞춘다. 기록상 옵션 탭 재편·분석 표시·수동 갱신·정렬 잠금이 빠졌을 수 있다.
2. SQL 에디터와 노코드→SQL 단방향 전환을 제공한다.
3. 사용자 삭제·비활성 흐름을 완성한다.
4. 대규모 카탈로그의 서버 검색·가상 스크롤을 추가한다.
5. 접근성·다국어·고대비·RTL·확대 배율 회귀 검증을 추가한다.
