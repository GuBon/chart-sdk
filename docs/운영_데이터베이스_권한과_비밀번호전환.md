# 운영 데이터베이스 권한과 비밀번호 전환

**작성일:** 2026-08-06<br>
**범위:** 메타 DB migration/runtime 역할 분리, 원본 DB 전체 읽기, Flyway V8 배포, legacy 평문 비밀번호 전환

## 운영 보안 선택 근거

| 개선 목표 | 현재 선택 | 검토 대안 | 선택 이유와 현재 이점 | 한계·검증 |
|---|---|---|---|---|
| runtime 계정의 DDL·Flyway history 접근 차단 | migrator/runtime role 분리, callback이 `mc_*`만 grant | schema 전체 default privilege, 단일 superuser 계정 | 침해 시 영향 범위를 DML 대상에 한정하고 새 migration 뒤 권한을 반복 적용 | 배포 계정·secret 관리 필요. privilege IT |
| V8 누락 없는 artifact | SQL source/package 목록·바이트 검증 | 로컬 파일 존재 확인, 수동 배포 체크 | clean checkout·CI·bootJar가 같은 migration을 포함하는지 자동 판정 | 이미 적용된 migration은 절대 수정 금지 |
| 평문 password 무중단 전환 | resolver 계측→startup migration→strict fail-closed | 즉시 차단, 영구 fallback, 수동 UPDATE | 연결 중단 없이 평문 0을 관찰한 뒤 보안 부채를 강제 종료 | 키 회전·KMS는 후속. 실DB migration/E2E |
| 암호문 무결성 | AES-GCM+version prefix | hash, Base64, CBC만 사용 | 복원이 필요한 secret에 기밀성과 인증 tag를 함께 제공 | app+환경 키 동시 탈취는 막지 못해 최소권한 필요 |

관련 구현 사건과 검증 근거는 [개발 문제해결 이력](개발_문제해결_이력.md)을 참조한다.

## 1. 기능 보존 경계

- 차트 편집기, 차트 종류별 초안, SQL/builder 생성, sampling v9 및 v7 cache 호환 코드는 변경하지 않는다.
- Flyway V8은 `mc_chart_refresh_lease`, `mc_sample_cache_build_lease`와 expiry index만 추가한다.
- 기존 `mc_chart_cache.result`와 `mc_sample_row_cache`를 갱신하거나 삭제하지 않는다.
- 원본 datasource role은 view-only가 아니다. PostgreSQL 시스템 schema를 제외한 업무 table/view/materialized view를 읽으며 raw·quality 테이블도 포함한다.
- `mc_*`는 ChartSDK 내부 객체 예약 접두사이므로 기존 catalog 제외 정책을 유지한다.

## 2. 책임 분리

| 역할 | 책임 | 금지 |
|---|---|---|
| `chartsdk_migrator` | Flyway, `mc_*` DDL·소유권 | superuser, role/DB 생성, 애플리케이션 요청 처리 |
| `chartsdk_app` | 메타 DB `mc_*` DML과 serial sequence 사용 | schema/table DDL, Flyway history, 다른 DB 관리 |
| 고객별 source reader | 허용된 업무 schema 전체 SELECT | INSERT/UPDATE/DELETE/TRUNCATE/CREATE |

운영 role 생성·기존 객체 소유권 이전은 `ops/postgres`에서 수행한다. role 비밀번호는 SQL 파일에 저장하지 않고 배포 플랫폼 secret으로 설정한다.

```text
ops/postgres/01-create-roles.sql
ops/postgres/02-chartsol-runtime-grants.sql
ops/postgres/03-source-reader-template.sql
```

고객 DB 역할은 ChartSDK가 자동 생성하지 않는다. 고객이 제공한 읽기 계정의 권한을 그대로 사용한다.

## 3. Flyway 리소스 계약

마이그레이션 SSOT는 `docs/V*__*.sql`이다. Gradle `processResources`가 이를 `db/migration`에 복사한다.

`verifyFlywayResources`는 다음을 검증하고 `check`, `bootJar`의 선행 task로 실행된다.

1. `docs/V8__refresh_lease.sql` 존재
2. source와 packaged migration 파일 목록 일치
3. 각 migration byte 내용 일치
4. `afterMigrate__runtime_grants.sql` source/resource 일치

`afterMigrate__runtime_grants.sql`은 role이 존재할 때만 실행한다. `mc_*` table/sequence에만 runtime 권한을 부여하고 `flyway_schema_history`의 모든 runtime 권한을 회수한다. broad `ALTER DEFAULT PRIVILEGES ... ALL TABLES`를 사용하지 않는다. broad default grant는 Flyway history까지 노출하기 때문이다.

별도 Flyway 계정을 사용하지 않으면 Spring Boot가 기존 runtime datasource를 재사용한다. 운영 분리는 Spring 표준 환경변수로만 활성화한다.

```dotenv
DATABASE_URL=jdbc:postgresql://db.internal:5432/chartsol
DATABASE_USER=chartsdk_app
DATABASE_PASSWORD=<runtime secret>

SPRING_FLYWAY_URL=jdbc:postgresql://db.internal:5432/chartsol
SPRING_FLYWAY_USER=chartsdk_migrator
SPRING_FLYWAY_PASSWORD=<migration secret>
```

## 4. 데이터소스 비밀번호 구조

책임은 다음처럼 분리한다.

- `crypto/DatasourcePasswordCodec`: v1 AES-GCM 형식, encrypt/decrypt/isEncrypted
- `datasource/DatasourcePasswordResolver`: runtime의 legacy 허용/거부 정책
- `datasource/DatasourcePasswordRepository`: migration용 잠금 조회·조건부 update
- `datasource/LegacyDatasourcePasswordMigrationService`: 기존 v1 키 검증 후 평문 변환
- `datasource/DatasourcePasswordStartupGuard`: opt-in migration 및 strict startup 검증
- `metrics/DatasourcePasswordMetrics`: legacy fallback 횟수

Migration은 모든 `v1:` 값을 먼저 복호화한다. 하나라도 키 불일치·손상이면 평문 update 전에 전체 작업을 중단한다. 이후 legacy 행을 `SELECT ... FOR UPDATE`로 잠그고 다음 조건부 update를 수행한다.
`v2:`처럼 버전 마커는 있지만 현재 지원하지 않는 값도 평문으로 간주하거나 재암호화하지 않고 전체 변경 전에 실패한다.

```sql
UPDATE mc_datasource
   SET db_password_enc = :encrypted
 WHERE id = :id
   AND db_password_enc = :old_value
   AND db_password_enc NOT LIKE 'v1:%';
```

비밀번호, 암호문, datasource ID는 migration 로그나 metric label에 기록하지 않는다. 로그는 total/alreadyEncrypted/migrated/skipped 수만 기록한다.

## 5. 배포 절차

### 5.1 사전 점검

1. 메타 DB backup
2. `flyway_schema_history` V1~V7의 `success=true`와 checksum 검증
3. 운영 `DATASOURCE_ENC_KEY` 고정·백업 확인
4. 새 artifact에서 `verifyFlywayResources` 통과

checksum 불일치가 있으면 `repair`를 먼저 실행하지 않는다. 적용 당시 migration과 저장소 파일의 차이를 조사한다.

### 5.2 호환 배포

첫 배포는 기존 DB 계정을 유지하고 아래 설정으로 실행할 수 있다.

```dotenv
DATASOURCE_PASSWORD_ALLOW_LEGACY_PLAINTEXT=true
DATASOURCE_PASSWORD_MIGRATE_LEGACY_ON_STARTUP=true
```

부팅 순서는 Flyway V8 적용 → Spring bean 초기화 → password startup migration → readiness다. migration 실패 시 서버는 ready 상태가 되지 않는다.

확인 후 `MIGRATE_LEGACY_ON_STARTUP=false`로 되돌린다.

### 5.3 role 전환

1. `01-create-roles.sql` 실행
2. secret manager로 두 login의 비밀번호 설정
3. V8 적용이 확인된 뒤 `02-chartsol-runtime-grants.sql` 실행
4. runtime/Flyway 환경변수 분리
5. 제한 역할로 전체 smoke/E2E 실행
6. `postgres` 자격증명을 애플리케이션 환경에서 제거

role bootstrap SQL은 클러스터 관리 작업이다. V8 DDL을 수동 적용하는 용도가 아니며, V8은 반드시 Flyway history를 통해 적용한다.

### 5.4 strict 전환

```sql
SELECT count(*) AS legacy_passwords
  FROM mc_datasource
 WHERE db_password_enc NOT LIKE 'v1:%';
```

결과가 0이고 모든 datasource 연결 시험이 성공한 후:

```dotenv
DATASOURCE_PASSWORD_ALLOW_LEGACY_PLAINTEXT=false
DATASOURCE_PASSWORD_MIGRATE_LEGACY_ON_STARTUP=false
```

평문으로 보관된 이력이 있는 외부 DB 비밀번호는 노출 가능성에 따라 별도로 회전한다.

## 6. 배포 게이트

```sql
SELECT version, success
  FROM flyway_schema_history
 WHERE version = '8';

SELECT to_regclass('public.mc_chart_refresh_lease'),
       to_regclass('public.mc_sample_cache_build_lease');
```

권한 확인:

```sql
SELECT has_schema_privilege('chartsdk_app', 'public', 'CREATE'); -- false
SELECT has_table_privilege('chartsdk_app', 'mc_chart', 'INSERT'); -- true
SELECT has_sequence_privilege('chartsdk_app', 'mc_chart_id_seq', 'USAGE'); -- true
SELECT has_table_privilege('chartsdk_app', 'mc_chart_refresh_lease', 'INSERT'); -- true
SELECT has_table_privilege('chartsdk_app', 'flyway_schema_history', 'SELECT'); -- false
```

Metric:

- `chartsdk.datasource.password.legacy_reads`: strict 전환 전에도 안정적으로 0이어야 한다.

## 7. 테스트

- `DatasourcePasswordCodecTest`: v1 round-trip, legacy/wrong-key 거부
- `DatasourcePasswordResolverTest`: fallback 계측과 strict 차단
- `LegacyDatasourcePasswordMigrationServiceTest`: mixed 변환, wrong-key 선차단, 조건부 update skip
- `LegacyDatasourcePasswordMigrationIT`: 3 encrypted + 2 plaintext 실DB 변환, connection identity 보존
- `FlywayV8MigrationIT`: V7→V8, cache JSON 보존, 두 lease 만료·token fencing
- `RuntimeDatabaseRoleIT`: runtime DML/sequence, DDL/history 거부, source 전체 SELECT·write 거부
- `MultiSourceChartLifecycleIT`: v7 snapshot→v9 응답, 다중소스 cache·refresh 회귀
- real-backend Playwright: 제한 runtime role로 등록→원본 탐색→지도 저장·재진입→refresh→embed

로컬의 기존 Docker volume에는 새 init SQL이 소급되지 않는다. `RuntimeDatabaseRoleIT`는 로컬 role이 없으면 skip하지만 CI는 `CHARTSDK_REQUIRE_ROLE_IT=true`로 반드시 통과시킨다.

| 확인 항목 | 결과 |
|---|---|
| `chartsdk_app` superuser / CREATEDB / CREATEROLE | `false / false / false` |

## 8. 롤백

- V8은 additive이므로 애플리케이션 롤백 시 테이블을 삭제하지 않는다.
- 이전 서버는 추가 lease 테이블을 무시할 수 있다.
- v1 암호문은 기존 codec과 호환되므로 재암호화한 값을 평문으로 되돌리지 않는다.
- role 전환 문제는 runtime 환경변수를 이전 계정으로 되돌린 뒤 누락 권한을 보완한다.
- 만료되지 않은 lease를 임의 삭제하지 않는다. 만료 후 다음 acquisition이 인수하도록 둔다.
