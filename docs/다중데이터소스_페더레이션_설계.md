### sampling v6 확장 (2026-07-16)

- 각 PostgreSQL 소스의 카탈로그는 TABLE뿐 아니라 VIEW·MATERIALIZED VIEW와 관계 종류·물리화 뷰 갱신 상태를 전달한다.
- 단일/다중 소스 JOIN에 `sample`이 있으면 `SamplingPlanner`가 RESULT_RANDOM을 선택한다. JOIN+WHERE 결과를 모집단 CTE로 만든 뒤 DuckDB `reservoir(K ROWS) REPEATABLE(seed)`에서 행을 뽑고, 표본 CTE를 집계한다.
- DuckDB reservoir의 seed 재현성을 위해 해당 SQL에 한해서 `threads=1`로 실행한다. 비표본 페더레이션은 기존 스레드 설정을 유지한다.

### 코드리뷰 리팩토링 (2026-07-02)

8-앵글 코드리뷰(정확성 5 검증 → 크래시·오염 0건, 전부 안전 실패) 후 클린코드 4건 반영:

### 동명 테이블 크로스소스 조인 — 핸들 도입 (2026-07-02)

이전엔 테이블을 bare 이름으로 키잉해 서로 다른 소스/스키마의 **동명 테이블**(예: `ds1.public.users` ⋈ `ds2.public.users`)을 한 차트에 조인할 수 없었다(거짓 "중복 조인" 오류·백엔드 모호성 거부). **핸들(handle)** 로 해결:

- **핸들 = 한 차트 내 테이블 인스턴스의 유일 식별자.** 기본은 테이블 이름, 동명 충돌 시에만 프론트가 접미(`users_2`)로 구분. 컬럼 참조는 `handle.column` 을 prefix 로 쓴다.
- **SQL 은 이미 완전 한정**(`"ds1"."public"."users"` vs `"ds2"."public"."users"`, 단일 소스도 `"public"."users"` vs `"analytics"."users"`)이라 **SQL 별칭(`AS`)이 불필요**하다 — 핸들은 config·검증 계층에만 존재하고 SQL 출력에는 등장하지 않는다.
- **비충돌 차트는 완전 무변경**(핸들=이름) — 기존 차트 마이그레이션·SQL 출력 불변.
- 백엔드 `BuilderSqlBuilder`: `TableRef.handle` 추가, `knownTables`·`registerTable`·`resolveRef`·조인 체인 검사를 핸들로 키잉. 같은 핸들이 서로 다른 물리 테이블을 가리키면 거부(`Ambiguous table handle`).
- 프론트 `TableRef.handle` + `builder.ts`(`tableHandle`/`withUniqueHandle`·`refTable`·검증·마이그레이션), `NocodeBuilder` 조인 테이블 선택 시 유일 핸들 부여.
- 범위 밖: **자기조인**(완전히 동일한 물리 테이블 2회)은 SQL `AS` 별칭이 필요해 별도 후속.
- 검증: 백엔드 단위(크로스소스·크로스스키마 동명 조인 + 중복 핸들 거부), E2E(`users ⋈ users` UI 언블록).

## 0. 최적 설계의 핵심 통찰

스냅샷 모델이 설계를 가른다:

> **페더레이션은 "계산 경로"에만 존재하고, "서빙 경로"에는 존재하지 않는다.**

```
[계산 경로]  저장 · 수동 새로고침 · 에디터 미리보기
   builderConfig(N소스) → 라우터 → DuckDB 페더레이션(ATTACH) → rows → 변환기 → ECharts option → mc_chart_cache

[서빙 경로]  임베드(GET /charts/data) · 목록 미리보기
   mc_chart_cache 의 스냅샷을 그대로 반환   ← 소스 안 건드림, 오늘 단일 소스와 동일
```

이 분리에서 따라오는 결과:
- **임베드가 고객 DB를 두들기는 위험 = 원천 소멸**(서빙은 캐시만).
- **실시간↔캐시 긴장 = 소멸**(스냅샷이라 캐시가 당연).
- 신규 코드는 **계산 경로에만** 격리 → 회귀 표면 최소.
- 변환기·캐시·임베드 파이프라인 = **거의 그대로**.

## 1. 근거 (측정 완료)

Python PoC + Java Phase 0 스파이크로 실측.

| 검증 | 결과 |
|---|---|
| 2서버 read-only ATTACH (Java `duckdb_jdbc`) | 461ms(첫 회, 확장 로드 포함) |
| 1M ⋈ 1M + 필터 + 집계 | 265ms (1GB 메모리 내) |
| fan-out 100M 중간산출 + GROUP BY | 674ms, **OOM 없음**(스트리밍 → 메모리 안전) |
| push-down | JDBC 경로에서도 projection·filter·dynamic-filter 하강 확인 |
| read-only / 타임아웃 가드 | write 차단 · `setQueryTimeout` 동작 |

**엔진 판정:** 대형 팩트 교차 조인은 pushdown+스필 있는 실 엔진이 필요 → DuckDB. 스냅샷 모델로 **저빈도**가 되어 성능 압력은 더 낮아졌으나, 대형 팩트 처리에는 여전히 DuckDB가 최적(app-side Java 조인은 대형 중간산출 materialize로 OOM 위험).

## 2. 실행 라우팅 (하이브리드)

**계산 경로**에서 참조 distinct 데이터소스 수로 분기:

```
distinct datasource == 1  → [기존] BuilderSqlBuilder(PG) → QueryExecutor(HikariCP)   (무변경, 최고 성능)
distinct datasource >= 2  → [신규] BuilderSqlBuilder(DuckDB 렌더러) → DuckDbFederation
```

- **단일 소스 차트는 동작·성능·SQL 100% 그대로** → 회귀 위험 최소, 기존 자산·다중 스키마 작업 보존.
- 서빙 경로는 라우팅 없음(항상 캐시).

## 3. DuckDB 통합 — per-op 무상태 (Phase 0 반영)

스냅샷 모델의 저빈도 계산이라 **워밍 싱글턴 대신 per-op 무상태 연결**을 택한다(더 단순·안전):

```
compute 요청(다중 소스):
  conn = DriverManager.getConnection("jdbc:duckdb:")   // in-memory, per-op
  LOAD postgres                                         // 확장 번들 프리로드 → 빠름(다운로드 없음)
  ATTACH 필요한 datasourceId 들 (READ_ONLY, 복호화 자격증명)
  SET memory_limit / threads / temp_directory
  executeQuery(federatedSql)  →  rows
  close()                                               // 상태 없음
```

- 공유 상태·동시성·ATTACH 캐시 무효화 = **불필요**(무상태라). 저빈도라 연결 셋업 비용 무관.
- 의존성 = `org.duckdb:duckdb_jdbc:1.5.4.0` 단일 fat JAR(네이티브 번들). `postgres` 확장은 **빌드에 번들**(에어갭 대비, 런타임 INSTALL 제거).
- 가드: `READ_ONLY` ATTACH(✓) · `setQueryTimeout` · 기본 최종 `LIMIT 1000`(스냅샷 ≤1000행) · `memory_limit`+`temp_directory`(스필). 지도 포인트 빌더는 JOIN·WHERE 조건에 맞는 좌표를 전량 반환하는 계약이므로 최종 LIMIT만 해제하며, 타임아웃·메모리 상한은 그대로 유지한다.
- 자격증명: 기존 AES-GCM 복호화 재사용 → ATTACH 문자열. **로깅 마스킹 필수**.

## 4. 데이터 모델

현재: `mc_chart.datasource_id` 단일 FK.

**변경**
- `mc_chart.datasource_id` **유지** = primary(base 테이블 소스). 단일 소스 하위호환·목록 필터 보존.
- 신규 junction `mc_chart_datasource(chart_id, datasource_id)`: 참조 소스 집합. **owner-scope 강제** + **삭제 가드(409)** 역조회.
- `builder_config` 테이블 참조를 **구조화 객체**로(문자열 점 결합 금지 — 2단화 때 겪은 파싱 모호성 재발 방지):
  ```json
  { "table":  { "datasourceId": 2, "schema": "tandanji", "name": "events" },
    "joins": [ { "table": { "datasourceId": 5, "schema": "public", "name": "users" },
                "type": "inner",
                "on": { "leftColumn": "events.user_id", "rightColumn": "users.id" } } ] }
  ```
- 컬럼 참조(`xAxis`·`yAxis[].column`·`on`)는 **`"핸들.컬럼"`**(§11.2). 핸들은 기본 테이블 이름, 동명 테이블이 겹칠 때만 `users_2` 로 구분. 소스는 테이블 선언에서 해석.
- **하위호환 로더**: 기존 문자열 `table` → `{datasourceId: mc_chart.datasource_id, schema: 파싱|public, name}` 승격. 마이그레이션 0.

## 5. 식별자 · 카탈로그

- 최근 `schema.table`(2단)을 **`datasource.schema.table`(3단)** 으로 확장.
- `SchemaCatalog`는 `(schema, name)`별 컬럼과 `relationType(TABLE|VIEW|MATERIALIZED_VIEW)`·`estimatedRowCount?`·`populated?`를 함께 보존한다. **`FederatedCatalog`**는 `catalog(datasourceId)` 다수를 `(datasourceId, schema, name)` 키로 union한다. 소스별 `mc_`·시스템 스키마 제외를 유지한다.
- 식별자 화이트리스트 검증을 3단 전체로. 조인 컬럼 참조는 구조화 참조라 점 파싱 불필요.

## 6. SQL 생성 — RefRenderer 전략 (DRY)

별도 `FederatedSqlBuilder` 중복 대신, `BuilderSqlBuilder`에 **테이블 참조 렌더러**를 주입한다. WHERE/집계/조인/버킷 로직(이미 테스트된)은 한 벌 공유.

| 경로 | 테이블 렌더 | 실행 |
|---|---|---|
| 단일 소스(PG) | `"schema"."table"` (현행) | QueryExecutor |
| 다중 소스(DuckDB) | `"dsAlias"."schema"."table"` | DuckDbFederation |

- `TableRef` 에 `datasourceId` 추가, 렌더러가 `datasourceId → ATTACH 별칭` 매핑으로 출력.
- 방언 차이 극소: `DATE_TRUNC`·`ILIKE` 호환. 단일 물리 관계의 SYSTEM은 PostgreSQL `TABLESAMPLE`을 사용한다. 다중 소스 조인 표본은 DuckDB에서 JOIN+WHERE 결과 CTE 뒤 `USING SAMPLE reservoir(K ROWS) REPEATABLE(seed)`를 사용하므로 base 관계 하나에 TABLESAMPLE을 붙이지 않는다.
- **불변식**: 단일 소스 생성 SQL은 바이트 동일 유지(기존 테스트가 가드).

### 6.1 조인 결과 표본 파이프라인

```text
각 소스 READ_ONLY ATTACH
  → FROM + JOIN + WHERE 결과를 __chartsdk_population CTE로 투영
  → reservoir(K ROWS, seed)로 __chartsdk_sample 생성
  → 표본에 GROUP BY·SUM/AVG/STDDEV/... 적용
  → 숨은 표본 행수·모멘트를 sampling v6 메타데이터로 분리
```

이 순서는 base 관계만 먼저 뽑을 때 생기는 조인 선택률 편향을 막는다. 결과 행이 표본 단위이므로 1:N 조인의 중복 행도 각각 하나의 모집단 행으로 취급한다. SUM·COUNT는 외삽하지 않은 표본값이고, AVG·STDDEV·VARIANCE는 유효 표본 수 조건을 충족하면 RESULT_RANDOM의 95% 추정 구간을 제공한다.

## 7. 캐시 · refresh_mode (스냅샷)

- **다중 소스 기본 `refresh_mode = manual`**: 저장 시 1회 계산해 캐시 시드 → 이후 **명시적 새로고침에만** 재계산. `live` **금지**(서빙 경로 페더레이션 유발 방지). `ttl`은 "주기적 스냅샷 갱신"을 원할 때만 옵트인.
- 캐시 무효화 = 정의 버전(`definition_version`) 기준. 소스 값 변경은 추적 안 함(스냅샷).
- `mc_chart_cache` 는 **기존 그대로**(ECharts option + rows 저장). 변환기 무변경(federation rows도 동일 shape).

## 8. 서빙 경로 불변식 (안전)

> **DuckDB 페더레이션은 계산 경로에서만 호출된다. 임베드·목록 서빙 경로는 다중 소스 차트에 대해 페더레이션을 절대 호출하지 않고 캐시 스냅샷만 반환한다.**

- 이 불변식은 **`ChartComputeService.serve()` 단일 진입점**에 구현된다(임베드·미리보기 공유, 2026-07-02 통일). 다중/단일 판정은 `ChartComputeService.isMultiSource(chartId)` **단일 진실원**을 통한다.
- `EmbedChartService`(임베드): 다중 소스 차트는 **캐시-온리 서빙**. 캐시 부재 시(정상 흐름상 없음 — 저장이 시드) 페더레이션 대신 명시적 오류. → 고트래픽 표면에서 고객 DB 보호.
- 목록 배치 미리보기(`/charts/previews`)도 `serve()` 로 동일하게 캐시-온리.

## 9. 프론트엔드 — 사이드바 탐색 컨텍스트 방식 (2026-07-03 갱신)

교차 소스 복잡도를 **사이드바 데이터소스 선택**으로 다룬다(별도 "조인 행 데이터소스 드롭다운"은 두지 않음):

- **사이드바 데이터소스 = 탐색 컨텍스트.** 선택한 소스의 TABLE·VIEW·MATERIALIZED VIEW만 좌측 트리 + 우측 base/조인 드롭다운에 노출.
- **소스 변경은 비파괴** — 드롭다운 필터만 바뀌고 구성(테이블·조인·축·조건)은 보존한다(예전 "소스 바꾸면 초기화 확인 모달" 제거).
- **크로스소스 조인 흐름**: base 관계 선택 → 사이드바에서 타 소스 선택(구성 유지) → 우측 "조인" 행에서 그 소스의 관계 선택.
- **트리 테이블 클릭**: base 없으면 즉시 선택, 있고 다른 테이블이면 "기준 테이블 초기화" 확인 모달(브라우징 중 오클릭 방지). 같은 테이블 재클릭은 원본 미리보기만.
- **primary 데이터소스**(저장·실행 payload)는 사이드바가 아니라 **base 테이블의 datasourceId**에서 파생 → 백엔드 무변경(구조화 TableRef 가 소스를 운반).
- 드롭다운은 browse 소스 테이블만, 단 **현재 선택값이 타 소스면 유지용으로 표시**(선택이 blank 로 사라지지 않게, 출처 라벨 병기).
- `builderConfig` 참조는 `{datasourceId, schema, name, handle?}` 구조. 동명 테이블 조인 시 `handle`(users_2)로 컬럼 참조를 구분.

### 9.1 구현 기술·근거 (2026-07-03)

프론트만 변경(서버 0). 사용 기술과 그 근거:

| 선택 | 코드 위치 | 근거 |
|---|---|---|
| **React 로컬 상태 분리** | `ChartEditor` useState — `datasourceId`(탐색 소스)·`builder`(구성) | 세션 편집 상태라 서버/전역 스토어 불요. 소스와 구성을 별도 상태로 둬 "탐색 ≠ 구성"을 성립시킴 |
| **비파괴 소스 변경** | `changeDatasource = (id) => setDatasourceId(id)` (초기화·모달 제거) | 크로스소스 조인은 소스를 넘나들며 탐색해야 함 → 소스 변경이 구성을 지우면 조인 자체가 불가능. 그래서 드롭다운 필터만 바꾸고 구성은 보존 |
| **browse 필터 + 선택유지 규칙** | `NocodeBuilder`: `browseTables = tables.filter(ds===browse)`, `tableOptionsFor(current, exclude)` | 드롭다운을 선택 소스로 좁히되, 타 소스 base/조인 선택이 blank 로 사라지지 않게 현재 값은 옵션으로 유지(출처 라벨 병기). 컬럼 해석은 전체 `tables` 풀 유지 |
| **primary=base 파생** | `primaryDatasourceId = builder.table?.datasourceId ?? datasourceId` | 백엔드가 구조화 `TableRef` 로 소스를 운반 → 실행/저장 payload 의 primary 를 base 테이블에서 파생. **서버 계약 무변경**(라우팅은 `referencedDatasources` 가 담당) |
| **오클릭 방지 확인 모달** | `pendingBaseTable` state + 기존 `Modal` 재사용 | 사이드바 트리는 탐색 중 자주 클릭 → base 있을 때 다른 테이블 클릭 시 "구성 초기화" 확인. 드롭다운 직접 선택(의도적)은 모달 없이 초기화 |
| **핸들 재사용** | `withUniqueHandle`/`activeTables` ([admin/lib/builder.ts](admin/lib/builder.ts)) | 조인 UX 정합화가 동명 조인(§핸들)과 결합 — 새 헬퍼 없이 기존 것 재사용 |

**검증:** `tsc` 무오류 + Playwright E2E 통과(수치 [테스트_전략.md](테스트_전략.md)) + 실브라우저 라이브(docker-user-db.users → tandanji-db 전환 시 구성 유지·조인 드롭다운 tandanji 필터 → 동명 크로스소스 조인 실행). API 실패 그레이스풀 처리는 트러블슈팅_기록.md **L9** 참고.

## 10. 보안

- 자격증명: AES-GCM 복호화 → ATTACH 문자열, **로그 마스킹**(구조화 로깅 필터에 규칙).
- owner-scope: 저장/계산 시 참조 전 datasource 가 owner 소유인지 검증(junction FK + build-time).
- 화이트리스트: `FederatedCatalog` 로 소스별 `mc_`·시스템 스키마 제외. 3단 식별자 전수 검증.
- read-only + 타임아웃 + 1000행 = 기존 원칙 DuckDB 계층에서 재현(§3).

### 12.1 DB — `V3__multi_datasource.sql`
```sql
CREATE TABLE mc_chart_datasource (
    chart_id       BIGINT NOT NULL REFERENCES mc_chart(id) ON DELETE CASCADE,
    datasource_id  BIGINT NOT NULL REFERENCES mc_datasource(id) ON DELETE RESTRICT,
    PRIMARY KEY (chart_id, datasource_id)
);
CREATE INDEX idx_mc_chart_ds_datasource ON mc_chart_datasource(datasource_id);
```
- `mc_chart.datasource_id` 유지. 데이터소스 삭제 가드(409)를 이 junction 조회로 확장.
