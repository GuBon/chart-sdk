# 표본추출 계약

**문서 상태:** 현재 정본<br>
**기준일:** 2026-08-06<br>
**적용 범위:** 노코드 차트 실행, 단일·다중 데이터소스, 결과 캐시, 관리자 미리보기, 임베드 API와 SDK

이 문서는 표본 설정, 실행 방법, 통계적 의미, 응답 메타데이터와 사용자 표시 문구를 한 곳에서 정의한다. 다른 문서는 표본추출의 목적과 해당 화면·API의 책임만 설명하고 세부 알고리즘은 이 문서를 참조한다.

## 표본 설계 선택 근거

| 개선 목표 | 현재 선택 | 검토 대안 | 선택 이유와 현재 이점 | 한계·검증 |
|---|---|---|---|---|
| point 렌더 메모리·전송 제한 | 자동 point에만 K행 표본, 일반·OFF·manual은 의미 보존 | 모든 차트 LIMIT, 클라이언트 다운샘플링 | 결과 의미를 몰래 바꾸지 않고 대량 symbol 경로만 보호 | exact 대형 결과 비용은 남음. k6·policy fixture |
| 관계별 실행 비용·편향 균형 | INDEX_RANDOM·RESULT_RANDOM·SYSTEM·FULL_SCAN 혼합 planner | 모두 random sort, 모두 SYSTEM, 사전 정확 COUNT | PK·VIEW·JOIN·희소성 특성에 맞는 경로 선택 | planner 추정 오차는 runtime reservoir로 보완 |
| 사용자가 근사값을 정확값으로 오인하지 않게 함 | sampling v9에 method·실측 수·treatment·warning 전달 | 단일 `approximate` boolean, Admin 배지만 표시 | cache·API·SDK까지 집계 의미와 가정을 보존 | 통계 설명이 복잡해 UI 문구 회귀 테스트 필요 |
| SUM·COUNT 의미 정직성 | 전체 외삽 없이 표본 합계·개수로 표시 | 추정 N으로 자동 외삽 | planner 오차를 전체값처럼 숨기지 않음 | 전체 추정이 필요하면 명시 기능으로 별도 도입 |

알고리즘별 선택 근거와 한계는 이 문서의 계획·실행 방법 절에서 설명한다.

## 1. 보장 범위

| 경로 | 행 계약 | 보호 방식 |
|---|---|---|
| 관계 미리보기·원본 데이터 탐색 | 최대 1,000행 | SQL/JDBC materialization 상한 |
| 자동 원본 산점도·지도 산점도·지도 히트맵 | 기본 10,000행, 설정 최대 50,000행 | planner 표본 + FULL_SCAN runtime reservoir |
| 일반 집계 차트 | 전체 결과 | admission control과 JDBC cursor |
| 표본 OFF·manual·raw SQL 차트 | 사용자 설정 그대로 | 시스템이 임의로 축소하지 않음 |

자동 point는 서버 보관·JSON·브라우저 렌더 행을 K로 제한하지만, 실제 모집단 N을 확인하는 scan은 쿼리 timeout 안에 끝나야 한다. 표본 OFF 또는 raw SQL로 100만 행을 그대로 반환하는 경로는 streaming·columnar 전환 전까지 빠른 응답을 보장하지 않는다.

## 2. 저장 설정

표본 설정은 `builder_config.sample`에 저장한다.

```json
{
  "sample": {
    "mode": "auto",
    "method": "auto",
    "size": 10000,
    "seed": 48291
  }
}
```

| 필드 | 값 | 규칙 |
|---|---|---|
| `mode` | `auto` 또는 `manual` | 자동은 서버가 방법을 선택하고, 수동은 사용자가 크기를 지정한다. |
| `method` | `auto` 또는 `system` | `system`은 기존 물리 관계의 SYSTEM 경로를 고정하는 호환 옵션이다. |
| `size` | 1,000~50,000 정수 | 목표 표본 행 수 K. 자동 기본값은 10,000이다. |
| `seed` | 0~2,147,483,647 정수 | 같은 데이터·실행 순서에서 표본을 재현한다. |
| `rate` | 0.1~100, 소수 한 자리 | 레거시 SYSTEM 고정 경로에만 사용한다. 신규 UI는 행 수를 사용한다. |

무편향 표본의 정확도는 전체 대비 비율보다 표본 수 n에 의해 결정되므로 신규 설정은 퍼센트가 아니라 행 수를 받는다. Admin의 `다시 뽑기`는 새 seed를 만들며 seed는 캐시 정의 판정에도 포함된다.

## 3. 계획 선택

`SamplingPlanner`가 관계 유형, 조인 유무, 추정 행 수, 정수형 PK와 키 밀도를 보고 방법을 선택한다. 계획을 위해 정확한 `COUNT(*)` 전체 스캔을 수행하지 않는다.

| 설정·관계 | 계획 | runtime collector | 결과 |
|---|---|---|---|
| 표본 없음 | NONE | 사용 안 함 | 전체 정확 결과 |
| manual | SYSTEM·INDEX_RANDOM·RESULT_RANDOM·FULL_SCAN | 사용 안 함 | 사용자 지정 표본 또는 작은 결과 전체 |
| auto + 일반 차트 | FULL_SCAN 또는 관계별 계획 | 사용 안 함 | 작은 결과 전체 또는 planner 표본 |
| auto + point + planner 표본 | SYSTEM·INDEX_RANDOM·RESULT_RANDOM | 사용 안 함 | planner 표본 |
| auto + point + FULL_SCAN, N≤K | FULL_SCAN | 전량 보관 | 전체 정확 결과 |
| auto + point + FULL_SCAN, N>K | FULL_SCAN | Algorithm R | RESERVOIR_RANDOM |

작은 테이블의 기준은 추정 100,000행 이하다. `rate=100`도 표본 SQL을 만들지 않고 FULL_SCAN 정확 실행으로 취급한다.

## 4. 실행 방법

### 4.1 INDEX_RANDOM

단일 정수형 PK가 있고 키 밀도가 0.5 이상인 물리 테이블의 우선 경로다.

- seed 기반 난수로 `[min_pk,max_pk]`의 무작위 좌표를 만든다.
- 좌표 배열을 `unnest(?)`한 뒤 base table PK와 등가 조인한다.
- 존재하지 않는 키는 단순 miss이므로 실제 모든 행의 선택 확률은 같다.
- 밀도만큼 `K' = ceil(K / density)`로 oversample해 목표 K를 채운다.
- 뽑힌 키만 인덱스로 읽어 전체 스캔을 피한다.

### 4.2 RESULT_RANDOM

VIEW, 파티션 부모, 단일·다중 데이터소스 JOIN에 사용한다.

1. `EXPLAIN (FORMAT JSON)`으로 `FROM + JOIN + WHERE` 결과 행 수 `N_hat`을 추정한다.
2. `p = min(1, K / N_hat)`를 계산한다.
3. 해당 결과를 `__chartsdk_population` CTE로 고정한다.
4. `__chartsdk_sample`에서 `random() < p` Bernoulli를 적용한다.
5. 표본 결과에 집계한다.

명시적 JOIN에는 `OFFSET 0` 경계를 사용해 PostgreSQL과 DuckDB가 Bernoulli 조건을 JOIN 한쪽으로 밀어 넣지 못하게 한다. 1:N으로 증가한 각 결과 행이 하나의 모집단 행이며 같은 확률로 독립 선택된다. JOIN 없는 VIEW는 비싼 투영을 표본 행까지 지연할 수 있도록 불필요한 경계를 생략한다.

`sampleSize`는 목표 K이고 `sampledRowCount`는 확률적으로 변하는 실제 선택 행 수다. RESULT_RANDOM은 전체 random sort나 reservoir를 사용하지 않는다.

### 4.3 RESERVOIR_RANDOM

자동 원본 산점도·지도 산점도·지도 히트맵에서만 사용하는 runtime 안전장치다.

- planner가 FULL_SCAN을 선택했지만 실행 중 실제 N이 K를 초과할 때 활성화한다.
- Algorithm R로 전체 N을 세면서 메모리에는 K행만 보관한다.
- 같은 ResultSet 순서와 seed에서는 결정적으로 재생한다.
- `populationCount`는 전체 scan으로 확인한 N이다.
- `sampleSize`와 반환 `sampledRowCount`는 K다.
- manual 또는 표본 OFF 요청에는 몰래 적용하지 않는다.

### 4.4 SYSTEM

정수형 PK가 없거나 통계가 없거나, 키 밀도가 0.5 미만이거나, probe 예산을 초과할 때 사용하는 폴백이다.

```sql
SELECT "category", AVG("amount") AS "avg_amount"
FROM "sales" TABLESAMPLE SYSTEM (10) REPEATABLE (48291)
GROUP BY "category"
```

SYSTEM은 디스크 블록 표본이라 군집 편향 위험이 있다. 응답에 `BLOCK_SAMPLE_CLUSTERING` 경고를 포함하고 독립행 표본용 신뢰구간을 제공하지 않는다.

### 4.5 FULL_SCAN

표본 CTE와 숨은 표본 열을 모두 생략한다. 작은 결과 또는 100% 실행은 다음처럼 표시한다.

```json
{
  "approximate": false,
  "method": "FULL_SCAN",
  "valueMode": "exact"
}
```

## 5. 집계별 의미

| 집계 | 표본 결과의 의미 | `treatment` | 사용자 표시 |
|---|---|---|---|
| 원본값 `none` | 선택된 원본 행 | `ROW_SAMPLE` | 표본 원본값 |
| SUM | 표본 안의 합계, 전체 외삽 없음 | `SAMPLE_AGGREGATE` | 표본 합계 |
| COUNT | 표본 안의 개수, 전체 외삽 없음 | `SAMPLE_AGGREGATE` | 표본 개수 |
| AVG | 모집단 평균의 표본 추정값 | `SAMPLE_ESTIMATE` | 표본 평균·가능한 경우 95% 오차 |
| STDDEV·VARIANCE | 모집단 분산 통계의 표본 추정값 | `SAMPLE_ESTIMATE` | 정규성 가정과 95% 구간 |
| MIN·MAX | 표본에서 관측된 극값 | `OBSERVED_EXTREME` | 전체 극값 보장 없음 |
| COUNT DISTINCT | 표본에서 관측된 고유 개수 | `OBSERVED_DISTINCT` | 전체 고유 개수보다 작을 수 있음 |
| 정확 실행 | 전체 결과 | `EXACT` | 정확한 결과 |

SUM·COUNT는 전체값으로 외삽하지 않으며 `SAMPLE_AGGREGATE_ONLY` 경고를 보낸다. 전체 구성비가 필요할 때는 별도의 `% 점유율` 표현을 사용한다. 향후 `전체 추정값 보기`를 명시적으로 도입하기 전에는 자동 외삽하지 않는다.

## 6. 표본 수와 신뢰구간

집계 SQL은 사용자 결과에서 제거되는 숨은 열로 다음 값을 전달한다.

- 그룹별 `__chartsdk_sample_count`
- 전체 실측 `__chartsdk_sample_total`
- 시리즈별 비NULL `__chartsdk_sample_n_{i}`
- 필요한 평균과 표본표준편차

신뢰구간의 n은 그룹 전체 행 수가 아니라 해당 시리즈의 비NULL 유효 표본 수다.

- INDEX_RANDOM·RESULT_RANDOM·RESERVOIR_RANDOM의 AVG는 `z * s / sqrt(n)` 대칭 구간을 사용한다.
- STDDEV·VARIANCE는 그룹 값이 정규분포에 가깝다는 가정 아래 자유도 `n-1`의 카이제곱 비대칭 구간을 사용한다.
- 분산 계열 구간에는 `STDDEV_CI_NORMALITY_ASSUMED`가 항상 붙는다.
- 유효 n이 30 미만인 그룹은 구간을 생략하고 `SMALL_SAMPLE_GROUPS`를 붙인다. 다른 유효 그룹의 구간은 유지한다.
- SUM·COUNT·MIN·MAX·COUNT DISTINCT에는 모집단 오차구간을 제공하지 않는다.
- SYSTEM에는 블록 상관 때문에 독립행 공식을 적용하지 않는다.

시리즈 배지의 `±X%`는 그룹별 상대오차의 최댓값을 보수적으로 사용한다.

## 7. 응답 계약 v9

`sampling`은 저장 정의와 비교하는 스펙 필드, 실행 결과를 설명하는 실행 필드를 함께 가진다.

```json
{
  "sampling": {
    "version": 9,
    "mode": "manual",
    "requestedMethod": "auto",
    "sizeTarget": 10000,
    "seed": 48291,
    "approximate": true,
    "method": "RESULT_RANDOM",
    "valueMode": "sample",
    "populationEstimate": 1000000,
    "populationCount": null,
    "sampleSize": 10000,
    "sampledRowCount": 9998,
    "confidenceLevel": 0.95,
    "groups": [{ "key": "의류", "sampleCount": 500 }],
    "estimates": [
      { "series": "sum_amount", "aggregate": "sum", "treatment": "SAMPLE_AGGREGATE" }
    ],
    "warnings": ["RESULT_RANDOM_SAMPLE", "SAMPLE_AGGREGATE_ONLY"]
  },
  "approximate": true,
  "sampleRate": 10
}
```

| 구분 | 필드 |
|---|---|
| 스펙 | `mode`, `requestedMethod`, `rate?`, `sizeTarget?`, `seed?` |
| 실행 | `approximate`, `method`, `valueMode`, `populationEstimate?`, `populationCount?`, `sampleSize?`, `sampledRowCount?`, `confidenceLevel?`, `groups?`, `estimates?`, `warnings?` |

`approximate`와 `sampleRate`는 구버전 클라이언트를 위한 별칭이다. 신규 Admin·SDK는 `sampling`을 정식 계약으로 사용한다.

## 8. 캐시 호환

- builder 차트 재계산은 저장된 문자열 SQL이 아니라 현재 `builder_config`로 SQL을 다시 생성한다.
- 캐시 정의 비교는 스펙 필드만 사용한다. auto 계획이 실행 시 다른 method로 결정돼도 영구 cache miss가 되지 않는다.
- v7 캐시는 현재 스펙 필드가 모두 같을 때만 읽고 응답 시 v9으로 승격한다.
- v7에 없던 `populationCount`는 `null`로 둔다.
- 정의되지 않은 v8과 다른 버전은 cache miss로 처리한다.
- 실행 메타데이터는 chart cache, preview, embed API와 SDK까지 손실 없이 전달한다.

## 9. 관리자 화면과 SDK 표시

관리자 화면은 다음 설정을 제공한다.

- 사용 여부
- 자동 또는 직접 지정
- 직접 지정 시 1,000~50,000행 목표 크기
- 추정 행 수가 있을 때 `전체 약 N행 중` 안내
- 새 seed를 만드는 `다시 뽑기`

결과 화면은 method와 실제 `sampledRowCount`를 표시한다. 일반 결과 행 수와 집계 입력 표본 행 수는 서로 다른 값이므로 같은 숫자로 표현하지 않는다.

- RESULT_RANDOM: `결과 Bernoulli 행 표본`
- RESERVOIR_RANDOM: `결과 Reservoir 행 표본`
- 정확 실행: `전체 데이터 · 정확한 결과`
- SUM·COUNT: `표본 합계`·`표본 개수`
- 구간이 있으면 `95% 신뢰수준 · 오차 약 ±X%`

SDK는 `sampling.warnings`를 숨기지 않는다. STDDEV·VARIANCE는 정규성 가정을, SYSTEM은 블록 군집 위험을 표시한다.

## 10. 실행 경계와 검증

- 표본은 차트 결과에만 적용한다. 관계 미리보기와 `mode:"rows"`에는 적용하지 않는다.
- `agg:"none"`과 sample은 함께 사용할 수 있으며 `ROW_SAMPLE`로 실행한다.
- JOIN과 VIEW는 RESULT_RANDOM을 사용한다.
- 공간 Point/Polygon 컬럼 모드는 별도 geometry 표본 계약 전까지 sample과 함께 쓰지 않는다.
- 잘못된 mode, method, rate, size, seed는 SQL 생성 전에 `400 INVALID_REQUEST`로 거부한다. 조용히 보정하지 않는다.
- 같은 seed의 결정성을 위해 DuckDB RESULT_RANDOM과 RESERVOIR_RANDOM은 안정된 행 소비 순서와 단일 thread를 사용한다.

## 11. 운영 용량과 관측

표본 collector는 K행만 보관해야 하고 `populationCount / retainedRows`, reservoir 활성 횟수, 표본 OFF·manual 결과 불변을 관측 가능하게 유지한다. admission 예산, pool cap, 15·30·100 VU 부하 기준과 배포 gate는 [대용량 운영 설계](대용량_운영_설계.md), 실행법과 최신 테스트 수치는 [테스트 전략](테스트_전략.md)을 따른다.

## 12. 후속 확장 조건

다음 기능은 현재 계약에 자동으로 포함하지 않는다.

- 명시적 전체 추정값과 SUM·COUNT 외삽
- SYSTEM 블록 구조를 고려한 분산 추정
- 반복 표본과 오차 안정성 비교
- exact 대형 결과의 ResultSet streaming·spill·binary/columnar 전송
- 자동 point K에서도 느릴 때의 typed array·전용 renderer

실제 metric과 부하 재현으로 병목이 확인된 경우에만 추가한다.
