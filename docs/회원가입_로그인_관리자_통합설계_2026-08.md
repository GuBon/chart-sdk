# 회원가입·로그인·관리자 통합 설계

**기준일:** 2026-08-18  
**상태:** 개발 착수 전 기준 설계  
**범위:** Admin 콘솔, Spring Boot API, PostgreSQL 메타 DB, 외부 차트 임베드

## 1. 결정 요약

1. 회원가입은 완전 공개하며 `아이디·비밀번호·비밀번호 확인`만 받는다.
2. 로그인은 JWT가 아닌 PostgreSQL 저장형 세션을 사용하고, 브라우저에는 HttpOnly 세션 ID 쿠키만 전달한다.
3. 모든 일반 API는 현재 로그인 사용자의 `owner_id`와 **정확히 일치**하는 리소스만 다룬다.
4. `admin`도 일반 API에서는 자신의 리소스만 다룬다. 전체 조회는 `/api/v1/admin/**` 전용 API를 통해서만 한다.
5. 일반 사용자는 자신의 차트·데이터소스·차트별 임베드 키를 관리한다.
6. 임베드 자격 증명은 `1인 1토큰`이 아니라 **`1사용자·1차트당 1활성 cek1_* 키`**다.
7. 임베드 키의 발급·재발급·회수는 차트 소유자가 차트의 임베드 모달에서 수행한다.
8. 관리자는 키 발급자가 아니라 **사용자 관리자**다. 사용자별 임베드 사용 현황은 읽지만 타 사용자의 키를 발급·재발급·회수하지 않는다.
9. 관리자는 모든 사용자의 차트와 미리보기를 조회할 수 있지만, 1차 범위에서 타인의 차트를 수정·삭제하지 않는다.
10. 기존 `mc_user_token` JWT와 `/tokens` 화면은 신규 임베드에서 사용하지 않는 레거시다. 신규 발급을 중단하고 UI/API를 제거한다.

## 2. 용어

| 용어 | 의미 |
|---|---|
| 로그인 세션 | Spring Session이 PostgreSQL에 저장하는 Admin 콘솔 인증 상태 |
| 세션 쿠키 | 브라우저가 보유하는 HttpOnly 무작위 세션 ID |
| 임베드 키 | 외부 SDK가 사용하는 차트별 Bearer `cek1_*` |
| 레거시 토큰 | `mc_user_token`에 저장된 사용자별 JWT. 신규 임베드에서는 미사용 |
| 일반 모드 | 자신의 리소스만 다루는 공통 UI/API |
| 관리자 모드 | 전용 라우트/API에서 전체 사용자·차트를 조회하는 모드 |

UI와 문서에서 `토큰`이라는 표현을 신규 기능에 사용하지 않고 `임베드 키`로 통일한다.

| 자신의 데이터소스 CRUD·스키마·쿼리 | O | O |
| 타 사용자 데이터소스 연결정보·자격증명·스키마 조회 | X | X |
| 자신의 차트별 임베드 키 발급·재발급·회수 | O | O |
| 전체 사용자 목록·상세 | X | O |
| 사용자 활성화·비활성화 | X | O |
| 사용자 역할 변경 | X | O |
| 사용자별 차트·임베드 현황 조회 | X | O |
| 전체 차트 목록·상세·미리보기 | X | O |
| 타 사용자 차트 수정·삭제 | X | X |
| 타 사용자 임베드 키 발급·재발급·회수 | X | X |
| 기존 임베드 키 원문 재조회 | X | X |

### 3.1 관리자 자신의 리소스

`admin`이 일반 `/charts`, `/datasources`, `/embed-keys` API를 사용할 때는 `member`와 동일하게 자신의 `owner_id`만 통과한다. 서비스 계층에 `admin이면 owner 조건 생략`을 추가하지 않는다.

**예외(2026-08-19 결정): 차트 목록 읽기.** 관리자는 일반 차트 목록(`GET /charts`, `/charts/previews`)에서 모든 사용자의 차트를 본다. 각 항목의 `ownerId`로 콘솔이 내 차트/타인 차트를 구분해, 타인(또는 소유자 없는 레거시) 차트는 편집·임베드·복제·삭제 대신 **열기(읽기 전용)** 카드로 그리고 `/admin/charts/{id}` 읽기 전용 상세로 연다. 타인 차트의 카드 미리보기는 저장 스냅샷만 쓴다. 상세·변경 API 는 이 예외의 영향을 받지 않는다.

### 3.2 관리자의 타 사용자 차트 조회

관리자 전용 Repository는 명시적으로 owner 조건을 받거나 전체를 조회한다. 상세·미리보기는 허용하되 저장·삭제·복제·임베드 키 변경 API는 제공하지 않는다.

전체 차트 상세에는 저장된 차트 정의·SQL·옵션과 차트 미리보기 결과가 포함된다. 단, 타 사용자의 데이터소스 접속 정보·암호화된 비밀번호·자유 스키마 탐색·임의 쿼리 실행 권한은 포함하지 않는다. 관리자의 전체 차트 미리보기는 저장 스냅샷만 읽는다(`ChartComputeService.storedSnapshot`). 소유자 서빙 경로(`serve`)를 재사용하면 live 차트는 열 때마다, manual 차트도 스냅샷이 없으면 타 테넌트 데이터소스에 SQL을 실행하고 캐시를 덮어쓰므로 "임의 쿼리 실행 권한 없음" 원칙과 충돌한다. 스냅샷이 없으면 `404 SNAPSHOT_NOT_FOUND`로 끝나며 재계산은 소유자만 시작한다.

## 4. 화면 설계

### 4.1 공개 화면

- `/login`: 아이디, 비밀번호
- `/signup`: 아이디, 비밀번호, 비밀번호 확인

회원가입 성공 후에는 자동 로그인하지 않고 `/login?registered=1`로 이동한다.

### 4.2 일반 화면

- 차트 목록·편집기
- 데이터소스 목록·추가·수정
- 차트별 임베드 코드 모달
- 로그아웃과 현재 사용자 표시

별도의 `토큰 관리` 메뉴는 노출하지 않는다.

### 4.3 관리자 화면

관리자 화면도 공통 AppBar, 차트 카드, 필터, 미리보기 컴포넌트를 재사용한다.

```text
관리자
├─ /admin/users
│  ├─ 사용자 목록·검색·역할·상태
│  └─ /admin/users/{userId}
│     ├─ 계정 정보
│     ├─ 활성 세션 수
│     ├─ 소유 차트 목록
│     └─ 임베드 현황 집계
└─ /admin/charts
   ├─ 전체 차트 목록·소유자 필터
   └─ /admin/charts/{chartId} 읽기 전용 상세·미리보기
```

사용자 상세의 임베드 현황은 다음 집계만 보여 준다.

- 임베드 키가 한 번이라도 발급된 차트 수
- ACTIVE / EXPIRED / REVOKED 키 수
- 가장 최근 발급일
- 차트별 현재 임베드 상태

임베드 키 원문·발급·재발급·회수 버튼은 두지 않는다.

### 4.4 관리자 오조작 방지

- 관리자 모드 배지와 소유자명을 항상 표시한다.
- 타 사용자 차트는 저장·삭제·복제·임베드 버튼을 렌더하지 않는다.
- 페이지에 read-only 문구를 표시한다.
- UI 비활성화에 의존하지 않고 서버에 해당 mutation route 자체를 두지 않는다.

## 5. 인증 설계

### 5.1 회원가입

```http
POST /api/v1/auth/signup
X-CSRF-TOKEN: ...

{
  "username": "chart-user",
  "password": "...",
  "passwordConfirm": "..."
}
```

- 새 계정은 `role=member`, `is_active=true`, `auth_version=1`로 생성한다.
- 비밀번호는 Argon2id DelegatingPasswordEncoder로 저장한다.
- 비밀번호 정책은 복잡도 조건 없이 최소 8 Unicode code point만 요구한다.
- 확인값은 저장하지 않는다.
- 중복된 아이디는 `409 USERNAME_TAKEN`으로 응답한다.
- 가입은 세션을 만들지 않는다.

### 5.2 아이디 정규화

정규화 규칙은 응용프로그램과 마이그레이션에서 동일해야 한다. 표시용 `username`은 보존하고, 중복·로그인 비교에는 `username_normalized`만 사용한다.

기준 알고리즘:

1. Unicode NFKC
2. 앞뒤 Unicode whitespace 제거
3. `Locale.ROOT` 소문자화
4. 1~100 code point 검증

`UsernameNormalizer` 하나가 회원가입·로그인·관리자 작업·레거시 데이터 이전에 공통 사용된다. SQL `btrim/lower`와 Java `strip/toLowerCase`를 따로 사용하지 않는다.

### 5.3 로그인

1. 아이디·IP rate-limit reservation
2. 아이디 정규화
3. `DaoAuthenticationProvider` + Argon2id 검증
4. 세션 ID 교체
5. CSRF 토큰 교체
6. `SessionPrincipal`에 비밀번호 해시를 제거한 사본만 저장
7. 사용자당 활성 세션 3개를 초과하면 가장 오래된 세션 만료
8. `200 AuthUserResponse` + HttpOnly 쿠키

아이디 존재 여부와 관계없이 인증 실패는 항상 `401 INVALID_CREDENTIALS`로 통일한다.

### 5.4 세션 생명주기

- 유휴 만료: 8시간
- 사용자당 최대: 3개
- remember-me: 없음
- 브라우저 종료 후 쿠키: 비영속 세션 쿠키
- 역할·비밀번호·계정 상태 변경: `auth_version + 1`
- 비활성화: 세션 즉시 삭제 + `auth_version + 1`

`AccountStateFilter`는 **로그인 세션을 사용하는 Admin API에서만** 실행한다. 임베드·지도 자산·헬스 경로에는 적용하지 않는다.

### 5.5 로그아웃·만료 처리

- `POST /api/v1/auth/logout` 성공은 항상 204다.
- 세션 만료·계정 변경 401은 Admin 클라이언트의 인증 상태를 즉시 anonymous로 바꾼다.
- CSRF 만료는 실제 mutation이 수행되지 않은 경우에만 새 토큰으로 1회 재시도한다.
- 로그인 `next`는 `new URL(candidate, location.origin)`으로 파싱하고 `target.origin === location.origin`일 때만 허용한다.

## 6. 임베드 설계

### 6.1 키 범위

`mc_embed_key` 활성 행의 유일성은 `(user_id, chart_id) WHERE is_active=true`다. 사용자가 여러 차트를 임베드하면 차트별로 다른 키를 가진다.

이 모델은 다음을 보장한다.

- 키 하나로 다른 차트 ID를 열거할 수 없다.
- 특정 차트의 키만 교체해도 다른 임베드는 계속 동작한다.
- 스니펫에 chartId를 넣지 않는다.

### 6.2 소유자 기능

차트 임베드 모달에서:

- 키 발급
- 활성 키 재발급(기존 키는 `ROTATED`)
- 활성 키 회수(`MANUAL`)
- ACTIVE / EXPIRED / REVOKED 상태·만료일 확인
- 방금 발급한 키 원문 1회 복사

목록 API는 원문을 반환하지 않는다.

### 6.3 로그인과 분리

임베드 서빙은 로그인 세션과 독립이다.

- SDK `fetch`: `credentials: 'omit'`
- 서버: `/api/v1/charts/data` 전용 stateless SecurityFilterChain
- session repository: `NullSecurityContextRepository`
- session policy: `STATELESS`
- CSRF: 비활성
- CORS: 모든 origin, GET/OPTIONS, Authorization, credentials=false
- 인증: `Authorization: Bearer cek1_*`만 사용

로그아웃·세션 만료·동시 세션 퇴출·역할 변경은 이미 배포된 임베드를 중단하지 않는다.

임베드가 중단되는 사유:

- 키 만료·회수·재발급
- 차트 삭제
- 사용자 비활성화
- 임베드 비밀키 회전

### 6.4 사용자 비활성화

하나의 transaction에서:

1. `mc_user.is_active=false`
2. `auth_version=auth_version+1`
3. 해당 사용자 세션 삭제
4. 해당 사용자의 모든 ACTIVE `mc_embed_key`를 `USER_DISABLED`로 회수
5. 관리자 감사 로그 저장

재활성화해도 기존 세션과 임베드 키는 복구하지 않는다.

## 7. API 계약

### 7.1 공개·인증

| Method | Path | 인증 | 용도 |
|---|---|---|---|
| GET | `/api/v1/auth/csrf` | 공개 | CSRF 토큰 |
| POST | `/api/v1/auth/signup` | 공개+CSRF | 회원가입, 201 |
| POST | `/api/v1/auth/login` | 공개+CSRF | 로그인, 200 |
| GET | `/api/v1/auth/me` | 세션 | 현재 사용자 |
| POST | `/api/v1/auth/logout` | 세션+CSRF | 로그아웃, 204 |
| GET | `/api/v1/charts/data` | `cek1_*` | 외부 임베드 서빙 |

### 7.2 일반 사용자

기존 차트·데이터소스·스키마·쿼리·임베드 관리 API를 유지한다. 모든 리소스 조회·변경은 current user를 서버에서 주입하며 client ownerId를 받지 않는다.

### 7.3 관리자

```http
GET   /api/v1/admin/users?q=&status=&role=&page=&pageSize=
GET   /api/v1/admin/users/{userId}
PATCH /api/v1/admin/users/{userId}/status
PATCH /api/v1/admin/users/{userId}/role

GET /api/v1/admin/charts?ownerId=&q=&type=&page=&pageSize=
GET /api/v1/admin/charts/{chartId}
GET /api/v1/admin/charts/{chartId}/preview
```

`GET /admin/users/{id}` 응답:

```json
{
  "user": {
    "id": 7,
    "username": "chart-user",
    "displayName": "chart-user",
    "role": "member",
    "active": true,
    "createdAt": "..."
  },
  "summary": {
    "activeSessions": 2,
    "chartCount": 12,
    "embeddedChartCount": 4,
    "activeEmbedKeyCount": 4,
    "expiredEmbedKeyCount": 2,
    "revokedEmbedKeyCount": 3,
    "lastEmbedKeyIssuedAt": "..."
  }
}
```

임베드 원문은 어떤 관리자 응답에도 들어가지 않는다.

### 7.4 관리자 변경 보호

- 자신을 비활성화할 수 없다.
- 자신을 `member`로 낮추려면 다른 ACTIVE admin이 최소 1명 있어야 한다.
- 마지막 ACTIVE admin을 비활성화·강등할 수 없다.
- 역할·상태 변경은 `SELECT ... FOR UPDATE`로 admin 수 검사와 변경을 직렬화한다.
- 변경 성공 후 대상 사용자의 기존 세션을 만료시킨다.

### 7.5 최초 관리자

신규 회원가입은 항상 `member`만 만드므로 첫 `admin`은 배포 운영자가 DB 소유자 계정으로 1회 승격한다.

```sql
UPDATE mc_user
   SET role = 'admin',
       auth_version = auth_version + 1
 WHERE username_normalized = :normalized_username
   AND is_active = true;
```

실행 후 영향 행이 정확히 1건인지 확인하고 다시 로그인한다. 최초 admin이 만들어진 후의 역할 변경은 관리자 API를 사용하며, 회원가입 요청에서 role을 받지 않는다.

## 8. 백엔드 구조

### 8.1 일반 사용자 계층

- `SecurityCurrentUserProvider`가 current user ID를 제공한다.
- `ChartService`, `DatasourceService`, `EmbedKeyService`는 exact owner 검사를 강제한다.
- 서비스 메서드에 client가 준 ownerId를 전달하지 않는다.
- 다중 데이터소스는 기준·조인 데이터소스 전부의 소유권을 실행 전에 검사한다.

### 8.2 관리자 계층

```text
AdminUserController
  └─ AdminUserService
      ├─ AdminUserRepository
      ├─ SessionRevocationService
      ├─ EmbedKeyBulkRevocationService
      └─ AdminAuditService

AdminChartController
  └─ AdminChartQueryService
      └─ AdminChartRepository
```

관리자 조회에 기존 `ChartRepository.appendOwnerScope` 우회 플래그를 추가하지 않는다. 별도 Repository로 SQL과 인가 표면을 분리한다.

### 8.3 SecurityFilterChain

순서가 높은 체인부터:

1. **Embed chain**: `/api/v1/charts/data`, stateless, cookie/session 미사용
2. **Public asset chain**: `/maps/**`, `/actuator/health/**`, stateless
3. **Admin session chain**: `/api/v1/**`, CSRF + Spring Session + role/owner 인가

서빙 경계에 `permitAll()`만 적용하는 것은 세션 로딩을 막지 못하므로 불충분하다.

## 9. DB 설계

### 9.1 유지 테이블

- `mc_user`: username, normalized username, password hash, role, active, auth_version
- `mc_session`, `mc_session_attributes`: 로그인 세션
- `mc_chart`, `mc_datasource`, `mc_chart_datasource`: 개인 소유 리소스
- `mc_embed_key`: 사용자·차트별 임베드 키 이력
- `mc_auth_rate_limit`: 인증 요청 제한

### 9.2 관리자 감사 로그

```sql
CREATE TABLE mc_admin_audit_log (
    id              BIGSERIAL PRIMARY KEY,
    actor_user_id   BIGINT NOT NULL,
    action          VARCHAR(50) NOT NULL,
    target_type     VARCHAR(30) NOT NULL,
    target_id       BIGINT NOT NULL,
    details         JSONB NOT NULL DEFAULT '{}'::jsonb,
    request_id      VARCHAR(100),
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    FOREIGN KEY (actor_user_id) REFERENCES mc_user(id) ON DELETE RESTRICT
);
```

기록 대상:

- `USER_ACTIVATED`
- `USER_DISABLED`
- `USER_ROLE_CHANGED`
- 후속 비밀번호 초기화 기능을 선택할 경우 `USER_PASSWORD_RESET`

로그에 비밀번호·비밀번호 해시·세션 ID·임베드 원문·데이터소스 비밀번호를 기록하지 않는다.

### 9.3 레거시 `owner_id IS NULL`

로그인 사용자에게 자동 노출하지 않는다. 운영자가 귀속 대상을 확정한 후 `legacy_owner_backfill.sql`을 검토·실행한다. 0건을 확인한 후 별도 마이그레이션으로 owner 컬럼의 NOT NULL을 검토한다.

### 9.4 사용자 정규화 마이그레이션

기존 V13의 SQL `lower(btrim(username))`은 런타임 Java 정규화와 완전히 같지 않다. 첫 외부 배포 전이면 V13을 다음 단계로 재구성한다.

1. normalized column을 nullable로 추가
2. 동일 `UsernameNormalizer`를 사용하는 Java migration으로 백필
3. 충돌 목록을 명시적으로 보고하고 중단
4. 충돌 해소 후 NOT NULL + UNIQUE

이미 외부 환경에 V13이 적용되었다면 기존 migration을 수정하지 않고 새 보정 migration을 만든다. 이 판단은 실제 배포 이력을 확인한 후 한다.

### 9.5 레거시 JWT

- 신규 발급 API와 UI를 제거한다.
- `GET /charts/data`는 이미 `cek1_*`만 받는다.
- 첫 배포에서 `mc_user_token` 테이블을 삭제하지 않고 롤백·감사 이력으로 보존한다.
- JWT 발급·검증 실행 코드는 즉시 제거하고, 별도 보존 기간을 확정한 후 이력 테이블을 제거한다.

## 10. Rate limit·프록시

### 10.1 원자적 reservation

`assertAllowed()`와 `record()`를 분리하지 않는다. DB upsert가 현재 window의 횟수를 증가시키고 해당 요청의 허용 여부를 같은 statement에서 반환한다.

로그인은 Argon2 검증 전에 username·IP reservation을 소비한다. 성공하면 현재 요청의 reservation 1건만 보상하고, 다른 병렬 실패 횟수를 삭제하지 않는다.

기본 정책:

- signup IP: 5회 / 1시간
- login username: 실패 10회 / 15분
- login IP: 실패 50회 / 15분

병렬 요청이 모두 제한을 통과하는 TOCTOU를 허용하지 않는다.

### 10.2 Client IP

`request.getRemoteAddr()`를 바로 사용하지 않는다. 신뢰할 수 있는 리버스 프록시 뒤에서만 Forwarded/X-Forwarded-For를 해석한다.

- direct deployment: remote address
- trusted reverse proxy deployment: Spring forwarded-header 설정 + 플랫폼의 trusted proxy 설정
- 외부 요청이 임의 Forwarded 헤더를 직접 신뢰하지 않는다.

배포 문서에 환경별 설정을 명시하고, 프록시 IP 하나로 모든 사용자가 제한되지 않는지 통합 테스트한다.

## 11. CORS·CSRF·쿠키

### 11.1 Admin

- 운영 기본: Admin UI와 API 동일 origin
- 개발 CORS origin: 환경변수로 명시, credentials=true
- 허용 헤더: Content-Type, X-CSRF-TOKEN
- 변경 요청: CSRF 필수
- 쿠키: HttpOnly, SameSite=Lax, Path=/
- prod: `__Host-chartsdk-session`, Secure, Domain 없음

### 11.2 Embed

- CORS origin `*`
- credentials=false
- SDK credentials=`omit`
- Authorization 헤더만 인증에 사용

## 12. 오류 계약

| 상태 | 코드 | 용도 |
|---:|---|---|
| 400 | `VALIDATION_FAILED` | 필드 검증 |
| 400 | `PASSWORD_TOO_SHORT` | 최소 길이 |
| 400 | `PASSWORD_CONFIRMATION_MISMATCH` | 확인 불일치 |
| 401 | `AUTH_REQUIRED` | 로그인 필요 |
| 401 | `INVALID_CREDENTIALS` | 로그인 실패 |
| 401 | `SESSION_EXPIRED` | 세션 만료·auth_version 변경 |
| 401 | `USER_DISABLED` | 비활성 계정 |
| 403 | `CSRF_INVALID` | CSRF 검증 실패 |
| 403 | `ACCESS_DENIED` | 역할 부족 |
| 404 | `USER_NOT_FOUND` | 관리자 대상 없음 |
| 404 | `CHART_NOT_FOUND` | 차트 없음/소유권 숨김 |
| 409 | `USERNAME_TAKEN` | 아이디 중복 |
| 409 | `LAST_ADMIN_REQUIRED` | 마지막 admin 보호 |
| 429 | `AUTH_RATE_LIMITED` | 인증 요청 제한 |

소유권 범위 밖 리소스는 403이 아닌 404로 존재를 숨긴다. 관리자 API는 admin 역할이 없으면 403을 반환한다.

## 13. 테스트 전략

### 13.1 인증

- 공개 회원가입 201, 자동 로그인 안 됨
- 정규화된 아이디 중복 409
- Argon2id 해시 저장
- HttpOnly/SameSite/Secure 쿠키
- 세션 ID·CSRF 회전
- 8시간 유휴 만료
- 4번째 로그인이 가장 오래된 세션 만료
- 만료·비활성 세션의 401 계약
- 외부 `next` 리다이렉트 차단(백슬래시 포함)

### 13.2 소유권

두 사용자 A/B로 다음을 모두 검증한다.

- 차트 목록·단건·미리보기·수정·삭제·복제·갱신
- 데이터소스 목록·수정·삭제·연결 테스트
- 스키마·테이블 미리보기·표시명
- raw SQL·builder·다중 데이터소스
- 임베드 키 목록·발급·회수

타인 ID를 넣은 요청은 모두 404이며 실행·변경·캐시 무효화가 발생하지 않아야 한다.

### 13.3 관리자

- member의 `/admin/**` 403
- admin의 전체 사용자·차트 조회
- admin의 타인 차트 미리보기
- admin 일반 API는 자신의 리소스만 반환
- 타인 차트 mutation route 미존재/405
- 사용자 상태·역할 변경과 세션 만료
- 마지막 admin 비활성·강등 409
- 비활성화 시 세션·임베드 키 일괄 중단
- 감사 로그 생성 및 민감정보 미포함

### 13.4 임베드 분리

- SDK 요청의 `credentials=omit`
- 같은 origin에 유효하지 않은 로그인 쿠키가 있어도 유효한 `cek1_*`로 200
- 로그아웃·로그인 세션 만료가 임베드에 영향 없음
- 재발급·회수·만료·사용자 비활성화는 즉시 401
- 키로 다른 차트 ID 열거 불가

### 13.5 Rate limit

- 임계치 직전/직후
- window 초기화
- block 만료
- 성공 로그인 reservation 보상
- 수십 개 병렬 실패에서 상한 초과 인증 연산을 시작하지 않음
- 리버스 프록시 뒤에서 사용자 IP 분리

### 13.6 실제 백엔드 E2E

실제 E2E는 다음 순서를 자기 완결적으로 준비한다.

1. 테스트 계정 회원가입
2. 테스트 admin 역할 승격 fixture
3. 로그인
4. 데이터소스·차트·임베드 흐름
5. 관리자 사용자·전체 차트 흐름
6. 생성한 fixture 정리

제거된 사용자 선택 combobox와 `/tokens` 흐름을 더 이상 참조하지 않는다.

## 16. 개발 전 남은 사용자 결정

다음 한 가지는 현재 요구사항만으로 자동 확정하지 않는다.

### 비밀번호 분실 복구

이메일이 없으므로 자동 복구가 불가하다. 선택지:

1. **관리자 임시 비밀번호 초기화(권장)**: 임시 비밀번호를 1회 노출하고 다음 로그인 시 강제 변경
2. **1차 배포 미지원**: 운영 DB 수동 조치로만 복구

임시 비밀번호 방식을 선택하면 `must_change_password`, 비밀번호 변경 화면/API, 세션 제한을 이 설계에 추가한다.

`owner_id IS NULL` 레거시 데이터의 실제 귀속 사용자 선택은 코드 설계가 아닌 운영 데이터 결정이므로 별도로 수행한다.
