# ChartSDK 문서 안내

**정리 기준일:** 2026-08-06<br>
**원칙:** 한 규칙은 한 문서만 권위 있게 정의하고, 다른 문서는 링크로 참조한다. 사건 당시의 판단과 변경 과정은 이력 문서에 보존하되 현재 계약으로 해석하지 않는다.

## 문서구조 선택 근거

| 개선 목표 | 현재 선택 | 검토 대안 | 선택 이유와 현재 이점 | 검증·한계 |
|---|---|---|---|---|
| 계약 중복과 과거 값의 현행 오인 방지 | 전문 문서 SSOT·역사 이력 분리 | 한 거대 문서, 모든 문서에 같은 설명 복사 | 현재 규칙과 사건 근거가 서로의 목적을 침해하지 않음 | 링크·사건 ID coverage 검사 필요 |

## 2. 코드와 데이터의 최종 권위

문서보다 더 세밀한 구현값은 아래 원천을 따른다.

| 관심사 | 최종 권위 |
|---|---|
| 옵션 키·기본값·노출 조건 | `chart-options/optionRegistry.ts` |
| ColorBrewer 팔레트 원본·동작 | `chart-options/colorBrewerSchemes.ts` · `chart-options/palettes.ts` |
| 운영 ECharts option 조립 | Server Java 변환기 |
| 프론트 mock 조립 | MSW 테스트 미러(운영 권위가 아님) |
| SQL 안전성·실행 의미 | Server SQL builder/executor |
| 캐시 결과 시각 | `mc_chart_cache.computed_at` |
| DB 구조 | Flyway `V1`~`V9`과 `afterMigrate__runtime_grants.sql` |
| 테스트 절대 수치 | `테스트_전략.md` |

## 4. 정리 과정에서 바로잡은 과거 계약

- 실제 차트 실행은 고정 1,000행 제한이 없다. `mode:"rows"`와 관계 원본 미리보기만 최대 1,000행이다.
- 현재 DB 권위는 Flyway `V1`~`V8`이다. 초기 문서의 “5개 테이블/V1~V4”와 PDF의 Prisma 전제는 역사적 정보다.
- 현재 차트 대분류는 막대·선·원형·산점도·박스 플롯·행렬 히트맵·영역 지도·포인트 지도 8종이다.
- `builderConfig.table`은 단순 문자열이 아니라 데이터소스·스키마·관계명을 가진 구조화 참조다.
- 글꼴 옵션은 단일 `typography.mode`가 아니라 제목·축·범례 등 요소별 경로를 사용한다.
