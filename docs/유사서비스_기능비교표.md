## 10. 본 프로젝트 관점 정리

### 우리가 만드는 범위 (위 표와 매핑)

| 영역 | 우리 MVP | 비고 |
|---|---|---|
| 차트 생성 | 노코드 빌더(MVP, 날짜 버킷팅·원본 데이터 탭 포함) → SQL 직접 작성(2차) | Metabase 모델 |
| 차트 종류 | 막대·선·원형·분포 4종 | ECharts로 추가 종류(레이더·지도 등) 확장 여지 |
| 시각화 옵션 | 12종 (색 개별 지정 포함) | Grafana 옵션 패널 구조 |
| 대시보드 | ✗ (차트 단위 임베드로 대체) | 모든 경쟁 서비스가 보유 — 의식적 제외 |
| 임베딩 | div 네이티브 + JWT (핵심) | Metabase에선 💰인 영역 |
| 데이터 소스 | PostgreSQL 다중 등록 + 동적 풀 | Metabase/Redash 표준 구조 |
| 인증 | 사용자 토큰(MVP) + 임시 로그인 골격 → SSO 교체 | 임베드 구조는 인증 방식 무관 |
| 자동화·알림 | ✗ | 전 서비스 보유 — 후속 검토 대상 |

### 표에서 드러나는 시사점

1. 대시보드·알림·스케줄은 6개 서비스 전부가 가진 기능이다. 우리 MVP에서 뺀 것은 정당하나, 사용자 기대치에는 존재할 수 있다. Post-MVP 1순위 후보.
2. 네이티브 임베드 + 토큰 인증을 무료로 제공하는 곳은 Superset(guest token)과 MongoDB Charts(Mongo 전용) 정도다. 범용 + 가벼움 + PostgreSQL이라는 우리 포지션은 비어 있다 — 자체 구축 정당성 유지.
3. 쿼리 파라미터(변수)는 전 서비스 공통이며 임베드 차트의 활용도를 크게 높인다(예: 부서별로 같은 차트). 옵션 확장보다 먼저 올 가능성이 있는 요구 — 토큰·SQL 설계에 파라미터 자리를 염두에 둘 것.
4. Superset은 기능이 가장 넓지만(50+ 차트, RLS, 전 기능 무료) 운영 복잡도가 가장 높다(Celery, Redis 등). "기능 상한선" 참고용.
5. 행 수준 보안(RLS)은 대부분 유료 영역이다. 우리에게 "사용자별 자기 데이터만" 요구가 오면 유료급 기능을 만드는 것임을 인지하고 비용을 산정할 것.
