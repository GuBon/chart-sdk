## 계층별 책임 경계 (무엇을 어디서 잡나)

- **빌더 로직**: admin 단위가 순수 함수로, E2E가 UI 경유로 이중 커버. SQL 문자열 정합성은 서버 단위가 최종 권위.
- **SDK**: 분기 로직은 SDK 단위(echarts·fetch mock)로, **실픽셀 canvas 렌더는 라이브 스위프**가 담당(jsdom/happy-dom은 canvas 미구현이라 echarts는 mock).
- **레이아웃 규칙**: `chart-options/layout-contract-cases.json`을 서버 JUnit과 Admin Vitest가 함께 읽어 Java 운영 변환기와 MSW 미러의 상수·경로 결과를 고정한다. 컨테이너 폭에 종속된 제목 보정은 SDK 단위가 초기 setOption과 ResizeObserver 콜백을 모두 검증한다.
- **표본 계약**: `chart-options/sampling-contract-cases.json`을 서버·Admin이 함께 읽어 SUM/COUNT가 선택된 표본값 그대로이고 어떤 집계에도 비율 배율을 적용하지 않는 계산을 고정한다. 서버는 INDEX_RANDOM 숨은 시리즈별 n/모멘트→sampling v5 구간 계산과 캐시 보존을, Admin mock은 같은 응답 형태를, SDK는 표본 집계/통계 추정/정확 실행·95% 배지·경고 전파를 검증한다.
- **페더레이션**: SQL 생성은 서버 단위(`FederatedSqlBuilder`), 실행은 서버 통합 + 라이브 스위프(실제 두 물리 PG를 DuckDB ATTACH로 조인).
- **임베드·CORS·토큰**: 라이브 스위프가 EmbedController → CORS → 토큰 → canvas 전 구간 E2E. 서버 단위는 JWT 검증(`JwtTokenProviderTest`).

## 라이브 스위프 (실인프라 검증)

전제: 백엔드 :8080, 프론트 :3000(실백엔드 연결), 실데이터소스 2개(docker-user-db id1 / tandanji-db id2), CORS 허용 origin에 :3001 포함([CorsConfig.java](server/src/main/java/com/chartsdk/config/CorsConfig.java)).

절차(스크립트가 자동 수행): ① 사전 점검 + `__sweep_` 잔재 청소 → ② S1/S5/S7 UI 스모크 → ③ API 직접 run-builder(단일소스 + 크로스소스 페더레이션) → ④ 차트 저장(캐시 시드) → ⑤ SDK 정적서버(:3001)에서 `demo/embed.html` 렌더(canvas) + 위조 토큰 401 → ⑥ 정리(sweep 차트 삭제·토큰 회수).

규약: 쓰기 데이터는 **`__sweep_` 접두 + finally 정리**. 실데이터소스는 읽기만. 스크립트는 스크래치패드에 두고 **커밋하지 않는다**(실인프라·포트 하드코딩 의존).

## 알려진 한계·후속

- **MSW에 `/api/v1/charts/data` 부재** → SDK 임베드는 mock E2E 불가, 라이브 스위프 전용. (후속: MSW 핸들러 추가 시 SDK 선언형 스캔도 MSW로 커버 가능)
- **소유권 격리 미완**: 스키마·임베드 읽기 검사(`owner_id=? OR owner_id IS NULL`)·토큰 신원은 구현됐으나, 로그인 부재로 차트 생성 시 `owner_id`가 NULL → `OR NULL` 탈출구로 임의 토큰이 임의 차트 접근. auth 구현 시 owner_id 주입 + 탈출구 제거로 완성(설계는 됨).
- **사용자 삭제 API 부재**: `POST /users`만 있고 `DELETE` 없음 → 라이브 스위프 `__sweep_user` 정리 불가. S7에 사용자 삭제/비활성 필요.
- **프론트 컴포넌트 렌더 단위 테스트 없음**: React 컴포넌트는 E2E로만 커버(현 전략상 의도 — 컴포넌트 단위는 도입 안 함).
