## 2. 기본 검증

```bash
cd server

```

이 경로는 외부 DB 없이 결정적으로 실행돼 CI `verify` job이 항상 수행한다.

## 3. MSW 브라우저 E2E

```bash
npm run test:e2e
```

- Admin: `http://localhost:3100`
- `NEXT_PUBLIC_E2E_MSW=true`
- Next 산출물: `admin/.next-e2e`
- 테스트: `admin/e2e`
- 역할: 많은 UI 분기와 실패 상태를 빠르고 결정적으로 검증

MSW는 운영 서버 대체물이 아니다. Java SQL, datasource 암호화, DB catalog, CORS, JWT DB 검증은 아래 실백엔드 계층이 맡는다.

## 4. 실백엔드 브라우저 E2E

```bash
npm run test:e2e:real
```

전용 환경:

| 구성 | 주소/자원 | 격리 방식 |
|---|---|---|
| PostGIS 메타+소스 DB | `localhost:56432/chartsdk_e2e` | `real-e2e` compose profile, tmpfs, 매 실행 재생성 |
| Spring | `http://localhost:8082` | 전용 PID tree |
| Admin | `http://localhost:3001` | MSW=false, `.next-realtest` |
| SDK | Admin `/sdk.js` | 실제 embed snippet과 Bearer API |

검증 흐름:

1. 데이터소스 추가와 실제 연결 테스트
2. `geometry_demo.korea_sigungu_statistics` 선택
3. PostGIS Polygon 지도 실행·canvas 렌더
4. 차트 저장과 정식 `/data/.../{chartId}` URL
5. 저장 차트 재진입과 cache preview 복원
6. `POST /charts/{id}/refresh`와 preview 재조회, 마지막 계산 시각
7. 사용자 생성과 JWT 토큰 발급
8. 복사 가능한 embed snippet
9. 외부 문서에서 `GET /charts/data`와 실제 SDK canvas/caption

global teardown은 Admin/Spring 프로세스 트리와 `chartsdk-real-e2e-db` 컨테이너를 제거한다. 기존 3000/3100/5433/55433 개발 환경은 사용하지 않는다.

## 6. 계층별 책임

### 옵션·변환

- `chart-options/optionRegistry.ts`: 옵션 키·기본값·노출 조건의 권위
- Server Java converter: 운영 ECharts option의 권위
- Admin MSW converter: 프론트 테스트 mirror
- 공용 JSON fixture: Java와 TypeScript가 같은 대표 계약을 소비

옵션끼리 우선순위가 있는 규칙은 조건 함수를 한 곳에 두고 변환기와 편집기가 함께 소비한다. `movingAverageOverridesSort()`가 그 예로, 같은 함수가 MSW 정렬 분기와 `정렬` 컨트롤 잠금을 결정하며 서버 조건과의 일치는 `statistical-overlay-contract-cases.json`의 정렬 케이스 2개(정렬 적용 / 이동평균이 정렬을 덮고 숨긴 범례를 되살리지 않음)가 Java·TS 양쪽에서 고정한다.

### 캐시·갱신

- Server 단위: single-flight, SWR, chart version, corrupt cache miss
- MSW E2E: 갱신 loading/error/disabled/computedAt UI
- 실백엔드 E2E: 실제 캐시 재계산→preview→지도→embed

### 지도

- Admin 단위/E2E: 공간 컬럼 선택과 viewport 상태
- Server 단위: PostGIS SQL과 타입 제한
- Server IT: 실제 geometry/geography 변환
- 실백엔드 E2E: 등록부터 SDK canvas까지

### 임베드·토큰·CORS

- SDK 단위: API base, Authorization, render/dispose
- MSW S3: 생성한 snippet 자체의 선언형 렌더
- 실백엔드 E2E: 실제 Spring CORS, JWT/DB token, cached chart response

## 7. CI

`.github/workflows/ci.yml`은 세 job을 수행한다.

1. `verify`: typecheck, workspace unit, production build, Server unit
2. `integration`: PostgreSQL/PostGIS Server IT
3. `real-backend-e2e`: Chromium + PostGIS + Spring + MSW=false Admin

실백엔드 실패 시 `admin/test-results/real-e2e`의 screenshot, trace, Spring/Admin 로그를 artifact로 보존한다.

## 8. 수치 갱신 규칙

수치를 바꿀 때는 실제 runner 출력을 확인한다.

```bash
npm run test:unit
npx playwright test --config=admin/playwright.config.ts --list
npx playwright test --config=admin/playwright.real.config.ts --list
cd server
./gradlew test
./gradlew integrationTest
```

다른 PRD·설계·트러블슈팅 문서는 “최신 수치는 테스트 전략 참조”만 기록한다. 이는 과거 L7의 문서-코드 수치 불일치 재발 방지 규칙이다.

## 9. 알려진 한계

- Admin React 컴포넌트는 순수 함수 단위와 Playwright 중심이며 별도 component renderer 계층은 없다.
- `tandanji:15432` 외부 federation IT는 기본 CI에서 skip될 수 있다.
- 인증/owner scope가 완성되지 않아 실백엔드 E2E는 개발 사용자 컨텍스트로 실행한다.
- 성능·장시간 refresh·다중 Spring 인스턴스 부하 테스트는 아직 별도 계층이 없다.
